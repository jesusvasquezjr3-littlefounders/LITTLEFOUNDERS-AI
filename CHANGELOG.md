## Unreleased

### Security

- The security review of 2026-10-10 and its ten fixes, by the owner's order before the dashboard work starts ([[SECURITY-GUIDE]], D-045 to D-047). **Deploys:** the three deploy workflows run only for a push to this repository (a fork's branch called `main` could have been built and deployed with the deploy token: the repository is public); CI jobs are read-only, secrets reach steps through `env`, the Vercel CLI is pinned. **Mail relay:** the SMTP listener on the private network is removed and only this machine may submit (`127.0.0.1:2525`); the relay's child process gets only the variables it uses. **Mail packages:** `npm audit` in `email-server/` goes from 1 critical, 3 high and 1 moderate to 0 (`nodemailer` 10). **Account lock-out:** a browser that has signed in to an account before counts its code guesses and emails apart from strangers (`lf_kd`, `backend/src/services/knownDevice.ts`). **Shared computers:** onboarding answers reach a new account without asking only in the same sitting; later the sign-up asks the age with an empty field and erases answers that hold another age. **Mail service's key:** a database role of its own, `mail_service`, with the delivery history and nothing else (`0004_mail_least_privilege.sql`, `database/scripts/mint-role-key.mjs`, `MAIL_SERVICE_KEY` on the gateway and the mail service); the service key stays in Core. **Site headers:** a content security policy without inline or evaluated scripts, no framing, `nosniff`, a referrer policy and a permissions policy in `frontend/vercel.json`, with `scripts/security-headers.mjs` failing the build when the policy and the build disagree. **Analytics:** no tracker is given a query string, and none loads on `/unsubscribe` or `/auth/callback`. **Environment:** only `development` and `test` relax anything in `NODE_ENV`; anything else is production. **Minors:** signing out ends the session even when the access cookie has expired; a line of the mail history is kept 90 days and an account's lines are deleted with it. Also fixed on the way: the history line of a brand-new account's first code was lost, and the relay's report route took any JSON in `detail`. What was left for later is T-036 in [[BUILD-TASKS]].
- Second round of the security review, by the owner's order (D-048 to D-050): everything it had left for later that can be closed from the repository, and a rule that nothing is pushed or deployed until the rest is closed (T-036 in [[BUILD-TASKS]]). **Asking for a code:** a piece of work first (`GET /auth/challenge`, `backend/src/services/challenge.ts`, `frontend/src/lib/proofOfWork.ts`), an hourly allowance for addresses with no account that leaves the rest to existing ones (`NEW_ADDRESS_CODES_PER_HOUR`), the email always sent after the answer (the error `EMAIL_NOT_SENT` and its sentence are gone), visitors counted by IPv6 /64 and mailboxes by their real name. **Accounts:** no name or username before the age (`AGE_REQUIRED`); display names cannot look like a web address or pass for staff (`0005_review_followups.sql`, `isReservedName`). **Emails:** the relay sends nothing without TLS, verifies the smarthost's certificate and never delivers by itself (`forward_secure.js`, `no_direct_delivery.js`); a signed hook call is acted on once; unsubscribe tokens expire after 180 days; no address in the mail service's logs. **Repository:** actions pinned by commit; approval required on GitHub for every outside contributor's fork pull request; `react-router-dom` 7, so `npm audit --omit=dev` is clean in the three packages. **Decided by the owner:** Google Analytics collects (D-048).
