## Tooling actually used (agent/tools/content/)

The pipeline Codex settled into, in order:

1. `export-production.mjs` — pulls current `lesson_documents` into a local
   export dir + manifest.
2. `prepare-inventory.mjs <export-dir>` — reshapes the export into the
   `corpus/docs/` layout `gate.ts` and `image-inventory.mjs` expect.
3. Generate replacement art (Codex used its own built-in image generation
   here — this is the step a new agent's own image-generation mechanism
   replaces; everything else stays the same).
4. `upload-production.mjs <file>` (one image) or `upload-many-production.mjs`
   (batch) — `sharp` flattens transparency to white, resizes to 1328×1328,
   `transcodeToWebp(bytes, 'image/png', 82)` (same quality Prism uses in
   production), then `uploadFile(...)` to Depot (`bucket: 'lesson-images'`,
   `visibility: 'public'`). Reads `FILEBASE_URL`/`FILEBASE_INTERNAL_KEY` from
   stdin JSON — never hardcode or print them.
5. `build-image-ops-from-uploads.mjs` — turns the upload results into
   `applyOps.ts`-shaped op files, one per lesson.
6. `applyOps.ts` + `gate.ts` — applies the ops across all three locales and
   rejects anything that would introduce narrated text, break locale
   lockstep, or breach the segment/graded floors.
7. `write-production.mjs <release-json>` — PATCHes `lesson_documents` for a
   gate-passed lesson.
8. `publish-applied-orders.mjs` — finalizes a batch and writes the checkpoint
   file for it.
9. `prepare-dev-preview.mjs` — exports a lesson to
   `frontend/public/dev-lessons/` for a human to eyeball at `/dev/lesson-view`
   before trusting a batch.

`convert-production-pngs.mts` is the separate whole-catalogue PNG→WebP sweep
(already run; only needed again if a new PNG turns up).
`restore-order3-s10.mts` was a one-off fix for a specific mistake, not a
pipeline step.
