## Implementation and rationale

**Architecture.** `frontend/src/rebuild/family/console/` holds the rebuilt screens and imports nothing outside `rebuild/` and `i18n/` (`spec:check`'s UI boundary): `consoleApi.ts` (every Core call through an injected transport, every response shape-checked, refusals keep Core's code), `FamilyConsole.tsx` (F1), `ChildProgress.tsx` (F2), `ChildMentorTalks.tsx` (F3), `ChildControls.tsx` (the Tutor's own controls), `consoleParts.tsx`, `console.css` (tokens only) and `consoleFixtures.ts` (tests). The routes in `routes/app/family/` are adapters: `consoleSession.ts` binds the transport (a fresh token per call; a failure while the browser reports no connection becomes `NETWORK`, so the screens can say "offline"; Core's message is never read or shown, only its code, as `check-family-copy-tone` requires), the language, the mode and the router. The wave-1 panels keep their own data planes and are handed to the console per child, so every server rule they carry is untouched. Copy lives in `rebuild-family.json` (groups `familyConsole`, `familyChildAccount`, `familyChildConsent`, `familyChildProgress`, `familyChildMentor`, `familyMemoryNotes`), budgeted in `rebuild/copy-budget/family.test.ts` in three locales.

**F1 (SPEC F1, 02 §4.5, 03 §3.3).** A neutral page: the child's work wide, the family-wide pieces narrow; one column below an 840 px container. The page composes by child: the picker (only with two or more children; its choice is written to the address with `replace`, so "back" from a child's page returns to that child and an in-place change keeps the scroll, rule 13), the overview card (name and handle as data, coins and the chore streak as reward chips, "N to approve" only when non-zero, and links to progress, Mentor talks and coins), then five groups: Learning (B.10 narrative, B.13 bridges, B.21 learning-streak pause), Coins and chores (D.5 corrections, D.2 chore-streak pauses, D.14 Share places, D.17 independence level), Connections (E.* requests, graph, history, the old share links), Privacy and safety (usage data, microphone, D.22 research), Tutors and account (second-Tutor invite, the child's Tutors, account management). The E.13 profile-safety notice sits in the overview when a field keeps the child hidden. Beside it: add a child, this month's tip (D.23), safety notices, pending Tutor requests, the scope statement (D.20) and the data policy (D.21). A second Tutor arriving with `?join=` sees the invite first.

- *Add a child*: first name, username, passphrase (with reveal), optional birth date (native date field, not in the future), nothing else; the username is normalised as typed; Core's refusals are named (`USERNAME_IN_USE`, `PROFILE_FIELD_UNSAFE`, `KID_LIMIT_REACHED`, `VALIDATION_ERROR`); the confirmation repeats the username, never the passphrase, and does not celebrate. On an empty family the open form replaces the empty state, so the first view carries the form only.
- *Manage*: rename (the username stays, and says why), a new passphrase (cleared after saving), removal behind two gates: the typed username enables the action, then the design system's `DestructiveAction` asks once more with "Keep account" first and focused (02 §9.5, the gallery contract "no rebuilt surface renders a danger button directly"); a child without a username can never be confirmed; `held` is shown as "on hold, nothing deleted".
- *Usage data*: the design system's switch; it never flips before Core confirms and keeps the confirmed state on failure.
- *Microphone*: deliberately not a switch. "Allow microphone" shows the exact wording (the `legal` role, not shortened) and a second, deliberate press stores that rendered string verbatim with the locale; turning it off is one press; while policy offers no microphone to minors nothing is offered, and an earlier consent stays revocable. The wording now says "the Mentor" (OD-6); Core stores whatever was shown.

**F2 (SPEC F2, F.1/F.3).** The child's tree flattened to units of topics, each topic's state as a glyph and a word ("Done", "In progress", "To explore", "Review due"; never a deficiency), a unit progress bar with its value written, the stats in a two-column grid, "It starts after the placement check" and "still being built" when Core says so. Shares use the rebuilt `AchievementShare` (now the `berry` button role, "berry shares or invites", 02 §9.5, instead of accent: a screen with three shares had three accent buttons). The adapter calls the image transport; `sharing:check` was extended so a rebuilt screen that owns the buttons is checked instead of the adapter (below).

**F3 (SPEC F3, §1.9).** Order, most urgent first: flags (the chip carries severity in words; a course-choice flag says it has no talk to open), the Mentor's note (the note in force, each suggestion with what it would replace, an out-of-date suggestion marked before anyone taps; "no note and nothing waiting" is one line), the microphone, "How they learn" (C.7, closed labels, reset by the Tutor), the savings plan and kept boards by caption, then the talks with the narrative joined from structured data into whole translated sentences, the length ("Talking right now" instead of "0 messages"), how a talk ended when it was not the ordinary way, the full transcript (speaker in words on every line; activities with the prompt as plain words, the score and XP; the board's caption; the tray steps as signed coin amounts), older talks on request (a failed page keeps what is shown and offers the retry), and the 90-day retention. A different child never shows the previous child's flags (the route is keyed by child and the component resets on a new id).

## Decisions taken on the SPEC's conservative default (proposals for owner review)

1. **One child at a time.** The console shows one child's tools with a picker, not every child stacked (the mockup's parent screen is one child's week). Children are never compared.
2. **Links, not inline boards.** The overview links to Tasks (approvals), progress, Mentor talks and coins instead of embedding the approval queue and the card (the mockup draws both inline). Approvals stay on Tasks (F4, next checkpoint), where the D.18 reason rules live.
3. **The microphone consent appears on F1 and F3** (legacy: F1 only; the inventory lists it on F3). Both read Core, so they cannot disagree after a reload.
4. **The consent wording says "Mentor"** (OD-6) and "your child"; the stored text changes for new grants only. Native human review of this consent is recommended before launch (OD-11).
5. **Linked teens**: no rename, passphrase or removal controls (Core refuses them); one line says the teen manages their own sign-in.
6. **Course picker** appears only with more than one published course; the first course is the default, as before.
7. **Boards by caption on F3** until the Mentor lane's rebuilt board lands (see limitations).
