# F1.0 Twelve reading charts

Horizonte Visual, unit `readcharts`, branch `hz/readcharts` (cut from `feat/horizonte-visual`). This record is for the owner and for the next agent that touches the chart family. It states what shipped, what was decided without asking, and what is left for the owner.

Status: implemented and locally verified with focused checks only. Human product acceptance, a visual pass in a real browser and the push gate are not part of this block.

## What shipped

Twelve chart kinds join the closed `chartDataSchema` in `backend/src/services/v2ChartModel.ts`. Core now has 58 kinds: 25 core, 21 situational, 12 reading. `frontend/src/rebuild/learning/charts/chartModel.generated.ts` is the byte copy produced by `node agent/tools/sync-v2-chart-model.mjs` and is never edited by hand.

The gates live in `READING_CHART_GATES` and `chartAllowed` checks them after the situational gates, so Forge and Core refuse a chart outside its age band or subject with the same code path as every other kind. The age scope is declared per kind, not per sprint: nothing here reaches the 6-9 band.

New schema fields, all optional and all strict: `series[].error`, `rows`, `cells`, `ranges`, `samples`, `events`, `records`. Every field has a hard cap (listed in the schema) so a chart cannot grow past what 320 by 180 can draw. `chartProblem` validates each kind and refuses a label that starts with `~` on a reading kind (see "Model words").

Capabilities `visual.<kind>.v1` derive from `CHART_KINDS`, so the lesson capability parity gate needed no map edit.

## Decisions taken without asking

1. **Timeline is 10+, not 6-9.** The catalogue row said 6-9. A dated span chart needs a learner to read two dates and a length at once; the dates are locale-formatted digits and the chart has no picture to lean on. The kind is gated 10+ in code. Owner follow-up: confirm, or open a 6-9 variant with a single-axis year strip.
2. **Six-row cap for dot-plot, dumbbell and funnel.** At 320 by 180 with a 48 px reader, seven rows leave under 20 px per row and the row labels collide. The cap is in `chartProblem`, so Forge cannot author past it. Heatmap rows cap at 8 and parallel-coordinates records at 8, which is as many as the reader can step through without a long wrap.
3. **The browser smooths density and violin shapes.** The payload carries the raw sample (5-60 values) and `readingGeometry.ts` computes the kernel density with Silverman's bandwidth and one shared axis across groups, so heights compare. The author never types a curve.
4. **Graded charts stay choice-id graded.** No chart collects a free number. The three graded fixtures use reads with one unambiguous answer: a funnel absolute count, the first Lorenz point, the dot-plot maximum.
5. **Word labels are HTML, SVG text is numerals only.** This keeps the Copy Budget measurable (`data-copy-role` on every word), lets the text reflow for es-MX and pt-BR and lets a screen reader read them in order.

## Architecture

- `charts/readingCharts.tsx` is one lazy chunk holding the twelve renderers and the reader. `TeachingChart.tsx` loads it inside `Suspense` only when the kind is a reading kind, so a lesson with an old chart pays nothing.
- `charts/readingGeometry.ts` is pure: `scaleLinear`, `niceTicks`, `bandwidth`, `densityAt`, `densities`, `timelineLayout`, `heatShade`, `axisShare`, `lorenzPoints`, `lineEnds`, `markerPath`.
- `charts/readingWords.ts` is eager and small: the word map and the locale date writer. `charts/readingCopy.ts` holds en-US, es-MX and pt-BR notes, loaded with the chunk.
- Pure model helpers (`quantile`, `sampleSummary`, `regressionFit`, `lorenzCurve`, `funnelSteps`, `dayNumber`, `axisExtent`, `heatValue`, `chartTable`, `chartReads`, `chartFacts`) sit in the shared model so Core and the browser agree on every number; the table and the screen-reader description are computed from the model, never from the drawing.

### Model words

A string that starts with `~` is a word of the model (a table column, a cell, a read part such as `~median` or `~of first %`) and the browser translates it through `readingWords.ts`. An author label never starts with `~`, and `chartProblem` refuses one that does. Authored labels come per locale from Forge copy; model words come from the three-locale map, with the tests asserting that every token is present and translated outside en-US (`x` and `y` are the same word).

The older 46 kinds keep raw English table column tokens. That is a pre-existing flaw, listed under owner follow-ups, and was left alone to keep this block's blast radius to the new kinds.

## Reading, tap and keyboard (V4)

Every mark can be read without a pointer. Each chart renders a reader (`role="group"`, with a `role="status"` live region, `aria-live="polite"`):

- tapping a mark reads it, and the hit areas are whole rows, columns or bands rather than the visible mark alone;
- Previous and Next are 48 px `Button size="sm"` controls and wrap at the ends;
- Left and Right arrow keys step, Escape clears;
- the same reads fill the Show-as-table equivalent, which is on every chart.

No chart drags, so the 64 px handle rule does not apply to this block. Series hues use the existing sky, mint and berry tokens; the second channel is pattern, marker shape or dash, never hue alone.

## Motion

Component motion uses `var(--dur-component)` (250 ms), no spring, and sits only inside `@media (prefers-reduced-motion: no-preference)`. A CSS test asserts all three. Nothing celebrates (V5); there is no confetti, no pulse on correct, no sound.

## Layout limits

- viewBox 320 wide for every kind; the height follows the content (see Fix round).
- The timeline moves labels to the nearest free row and clamps them inside the drawing (`timelineLayout`).
- A dot-plot, dumbbell or funnel shows at most 6 rows; the heatmap at most 8 rows by 12 columns; parallel coordinates at most 6 axes and 8 records.
- es-MX and pt-BR label budgets are the Copy Budget with the 1.25 factor outside en-US. The render test checks body copy at the 10-12, 13-17 and adult bands.

## Fix round

Unit `fx-charts`, branch `hz/fx-charts`. Three jobs: the blank band above the legend of the heatmap and the timeline, dark mode of the reading charts, and one test that walks all 58 kinds. Focused vitest runs only; no browser, no dev server.

### 1. The blank band above the legend

Cause: every reading chart drew into a fixed 320 by 180 viewBox inside a 16:9 canvas and the canvas kept a fixed 24 px bottom margin for hanging labels. A three-by-two heatmap uses about 70 units and a three-event timeline about 30, so the legend sat under 100 units of nothing.

What changed:

- Each plot returns its own `height`, and the viewBox, the canvas `aspect-ratio` and the label `top` percentages all use it. Heights for the sample data: timeline 46, heatmap 78, dumbbell 133, error bars 160, violin 160, fan 160, parallel 162, Lorenz 168, dot plot 169, funnel 172, density 176, regression 176. Nothing is taller than 180.
- The canvas is capped at `min(568.9, 320 * 320 / height)` px wide, so a tall plot never grows past the old 320 px height and the HTML labels stay aligned to the SVG (the fit canvas turns `max-block-size` off).
- The words that hang under or over the marks are measured, not guessed: `useFittedTags` writes `--lf-chart-over-top` and `--lf-chart-over-bottom` (px, shown labels only) on a `lf-chart-canvas--fit` host, and the canvas margin is those two values plus `--spacing-2`. Before the first measure (and in jsdom) the margin falls back to the old `--spacing-4`.
- Heatmap: the row-label column is sized from the longest word (44 to 96 units), rows wrap to two lines, and the cell height follows (18 to 38).
- Timeline: label room follows the longest word (64 to 96), the rows above and below the axis are as tall as the labels that sit in them, and `timelineLayout` now places left to right and refuses a row where a stem to a far row would cross a nearer label.
- Dot plot, dumbbell and funnel keep a minimum row height so two 16 px labels never overlap; parallel coordinates sizes its end-axis margin from the longest axis word.
- Funnel height is the end of its last tap row, so no tap area leaves the viewBox.

Other kinds, checked at 320 wide (scale 1, which is the narrowest slot the board gives a chart; I read "compact slot" that way): no clipped numerals, no mark outside the viewBox, and no blank band over 20 units top or bottom. `readingCharts.test.tsx` pins those bounds for all twelve kinds in the three locales.

### 2. Dark mode

Audit result: every colour the reading charts and `TeachingChart.tsx` use is a `var(--token)` and every one of those tokens flips in `.lf-rebuild[data-theme="dark"]`; there is no `--ink`, `--primary`, `--sky`, `--mint`, `--berry`, `-ridge` or `--on-*`, and no hex, rgb or named colour. The defects were contrast, not tokens:

- Axes, the Lorenz and parallel axes and the error-bar whiskers used `--outline` (1.38:1 on the dark surface, 1.42:1 on the light one). Axes now use `.lf-chart-baseline` (`--edge`, 3.6:1 light, 3.02:1 dark) and whiskers `.lf-chart-whisker` (`--content-muted`). Gridlines stay on `--outline`: they are decoration, the numerals carry the values.
- Heat cells: the empty cell is `.lf-chart-cell` (`--sunken` with an `--outline` edge), and the deepest shade is capped at `HEAT_CEILING` 0.76. With `--content` text over `--sky-strong` on `--sunken` that keeps 4.5:1 at every step in both themes (4.67:1 in dark, the tight side). The text halo was removed: it was a light-only fix.
- `chartsDark.test.ts` parses `tokens.css` and fails if any of the three chart sources uses a token that has no dark value or a raw colour, if the retired classes come back, if the baseline or whisker rule changes token, and if the heat text, the axes, the whiskers and the three series hues drop under 4.5:1 (text) or 3:1 (marks) in either theme.

### 3. Table path and descriptions

- `data-label` on every table cell. The stacked table at widths under 840 px prints `attr(data-label) ': '` before each cell; without it every cell showed a bare colon.
- Link labels of `flowchart`, `decision-tree` and `tree` are a third cell with no model column. The table now pads every row to its widest row and the extra column is headed "Label" (`chartCopy.label`, three locales).
- Seven diagram kinds (`flowchart`, `decision-tree`, `tree`, `org-chart`, `swimlane`, `ishikawa`, `mind-map`) pointed `aria-describedby` at an empty paragraph, because `chartFacts` has nothing numeric to say about a diagram. The description is now the structure, built from the table (`Income → Save (yes); Income → Spend (no)`). This is in `TeachingChart.tsx`, not the model, so `chartModel.generated.ts` is still a byte copy of the backend.

### Decisions taken without asking

1. **Heat ceiling 0.76, not a new token.** Deepening the cell ink is cheaper than adding a token pair, and the cap is a pure constant the test reads.
2. **7.4 px per character** (`GLYPH`) to size label rooms before the browser measures. It errs wide for Latin text at the 14 px bold caption size; `useFittedTags` still hides a label that does not fit, so a wrong guess costs a label, never an overlap.
3. **Hide, never shorten.** Band-width labels (error bars, violin and fan with many categories) that do not fit stay hidden by the data-fit rule and the table carries them.
4. **The older 46 kinds keep their viewBox and their English table column tokens.** Only `TeachingChart.tsx` table padding, `data-label` and the diagram description touch them.
5. **No new chart data field.** The model and the Core schema are unchanged.

### Limits

- jsdom has no layout. Every number above comes from the geometry the chart hands to the browser, and the overhang margin was exercised with mocked rectangles. Nobody has looked at these charts in a real browser, in either theme, at 320 or at desktop width. That check is still the owner's (follow-up 3 above).
- A crowded timeline keeps every mark and every tap area inside the box (tested with eight long labels); a label that cannot find a free spot in a real browser is hidden by the data-fit rule and the table lists it.
