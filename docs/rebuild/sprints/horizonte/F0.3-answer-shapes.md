# Horizonte Visual F0.3: new answer shapes

Piece: F0.3 of the Horizonte Visual build (unit "shapes", core shared primitive). Status: implemented and locally unit-tested on branch `hz/shapes`. Not verified at the push gate, not accepted, not released. See "What is not claimed".

## What this adds

Four pure answer-shape scorers that visual packs call from their pack scorer. Each shape has a response format, a rubric format, an optional context supplied by the pack from its own payload, a sample response, and the full verdict ladder `invalid | valid | review | met` with the existing closed diagnostic codes. No new `V2VisualKind`, no new diagnostic code, no new segment type and no change to the Oracle context schema.

| Shape id | Question it answers | Typical visual |
|---|---|---|
| `number.tolerance` | Is a typed or dialed number close enough to the target? | Read a value from a chart, estimate a quantity |
| `points.set` | Did the learner mark the required 2-D points, and only those? | Plot points, mark intercepts, mark a region corner |
| `curve.parameters` | Did the learner fit the right line, quadratic or exponential? | Drag sliders until the curve matches |
| `arrangement.slots` | Which piece goes in which slot, in what order, how many times? | Sort, sequence, match, fill a diagram |

Files:

- `backend/src/services/v2AnswerShapes.ts`: the canonical pure module. Import-free, so a byte copy is valid anywhere.
- `backend/src/services/v2AnswerShapeSchemas.ts`: Core-only zod schemas for responses and rubrics (the only file that imports zod).
- `frontend/src/rebuild/learning/v2AnswerShapes.generated.ts` and `coursegen/src/v2/v2AnswerShapes.generated.ts`: byte copies, generated by `node agent/tools/sync-v2-answer-shapes.mjs` and checked with `--check`. Never hand-edit them.
- `agent/tools/sync-v2-answer-shapes.mjs` and its `node --test` file.
- Tests: `backend/src/__tests__/v2AnswerShapes.test.ts`, `backend/src/__tests__/v2AnswerShapesCurveArrangement.test.ts`, `frontend/src/rebuild/learning/v2AnswerShapes.test.ts`.

Gate wiring: the root `spec:check` and `backend/scripts/contract-check.ts` both run `sync-v2-answer-shapes.mjs --check`.

## Common contract

Every scorer has the signature `(response: unknown, rubric?: unknown, context?: unknown) => ShapeGrade`, with `ShapeGrade = { verdict, diagnostic }`. `ShapeGrade` is structurally a `V2Grade` (`shapeGradeAsV2Grade` in the schemas module proves it at compile time), so a pack scorer can return it unchanged.

- Never throws. Any input, including `null`, cycles, `BigInt`, symbols, huge arrays, huge strings and `JSON.parse` output with a `__proto__` key, produces a grade.
- No rubric: a well-formed response is `valid`. A malformed response is `invalid`.
- A malformed rubric or context is `invalid`, never a guess.
- A well-formed response that does not meet the rubric is `review` with one diagnostic. A response that meets it is `met` with diagnostic `none`.
- Diagnostics used, all already in `V2_DIAGNOSTIC_CODES`: `none`, `structure`, `value`, `partial`, `miss`, `false_alarm`, `tolerance`.
- Aggregate convention for set-like shapes: missing and surplus gives `partial` (if anything matched) or `value` (if nothing did), missing only gives `miss`, surplus only gives `false_alarm`.
- Exact arithmetic. Numbers and curves are compared as BigInt rationals and points as BigInt micro-units. No float comparison decides a verdict, so a boundary case gives the same answer in every engine.
- Untrusted keys are read with `Object.keys` against exact whitelists, held in `Map` and `Set`, and never written onto plain objects. The id pattern admits `constructor`, so slot and piece ids are never used as property names on a shared object.
- Entry points: `gradeNumberTolerance`, `gradePointSet`, `gradeCurveParameters`, `gradeArrangement`, plus the dispatcher `gradeAnswerShape(shape, response, rubric?, context?)`, the sample builders `sampleNumberTolerance`, `samplePointSet`, `sampleCurveParameters`, `sampleArrangement`, the dispatcher `answerShapeSample(shape, rubric, context?)`, and `isAnswerShapeId`.

Numeric text grammar (number tolerance and curve parameters): decimal `^-?(0|[1-9]\d{0,14})(\.\d{1,12})?$` or fraction `^-?(0|[1-9]\d{0,14})\/[1-9]\d{0,14}$`, at most 32 characters. Exponents, `NaN`, `Infinity`, leading `+`, whitespace and leading zeros are all invalid.

Tolerance object: `{ absolute?: string, relative_bps?: 0..10000 }`. The allowance at a target is `max(absolute, |target| * relative_bps / 10000)`.

## 1. `number.tolerance`

- Response: `{ value: string }`.
- Rubric: `{ target: string, tolerance?: Tolerance, review?: Tolerance }`. No `tolerance` means exact match. `review` is the near-miss band and must be strictly wider than the met band, otherwise the rubric is malformed.
- Context (optional): `{ minimum?: string, maximum?: string }`, the dial or axis range. A response outside the range is `invalid`. The target must lie inside it, and the met allowance must be smaller than the span.
- Verdicts: within the met allowance gives `met`. Within the review band gives `review` with `tolerance`. Anything else gives `review` with `value`.

Pack scorer call:

```ts
import { gradeNumberTolerance } from './v2AnswerShapes.js';
import { shapeGradeAsV2Grade } from './v2AnswerShapeSchemas.js';

function scoreReadValue(payload: ReadValuePayload, response: unknown, rubric?: unknown): V2Grade {
  const context = { minimum: payload.axis_min, maximum: payload.axis_max };
  return shapeGradeAsV2Grade(gradeNumberTolerance(response, rubric, context));
}
```

Rubric example: `{ "target": "4.5", "tolerance": { "absolute": "0.25" }, "review": { "absolute": "1" } }`. `4.6` is met, `5.2` is `review/tolerance`, `8` is `review/value`.

## 2. `points.set`

- Response: `{ points: [{ x: number, y: number }] }`, order-independent. Exact duplicate coordinates are `invalid`.
- Coordinates: finite numbers, magnitude at most 100000, at most 6 decimal places (quantized to micro-units).
- Rubric: `{ required: Point[1..32], forbidden?: Point[0..32], snap?: number, extra?: 'forbid' | 'allow' }`. `snap` is the snap radius, default 0, at most 1000. Required and forbidden points must be farther apart than twice the snap radius, so snap discs never overlap and matching is unambiguous. A response point inside a required disc matches it; a second point inside an already matched disc counts as extra.
- Context (optional): `{ minimumX, maximumX, minimumY, maximumY, step?, maxPoints? }`. With a context, every response and rubric point must lie in the box and on the `step` grid, and the response may hold at most `maxPoints` (up to 64). Without a context the response may hold at most 32 points.
- Verdicts: all required matched and nothing forbidden hit and no extras (unless `extra: 'allow'`) gives `met`. Otherwise `review` with `miss`, `false_alarm`, `partial` or `value` per the aggregate convention. Any forbidden hit counts as surplus.

Pack scorer call:

```ts
import { gradePointSet } from './v2AnswerShapes.js';

function scorePlot(payload: PlotPayload, response: unknown, rubric?: unknown): V2Grade {
  const context = { minimumX: payload.x.min, maximumX: payload.x.max, minimumY: payload.y.min, maximumY: payload.y.max, step: payload.grid_step, maxPoints: payload.max_points };
  return shapeGradeAsV2Grade(gradePointSet(response, rubric, context));
}
```

## 3. `curve.parameters`

- Families and parameter names: `line` is `m, b` (y = m x + b), `quadratic` is `a, b, c` (y = a x^2 + b x + c), `exponential` is `a, b` (y = a * b^x, base `b` greater than 0).
- Response: `{ family, params: { <name>: string } }`. The parameter names must match the family exactly.
- Rubric: `{ family, target, by?, parameter_tolerance?, parameter_review?, samples?, curve_tolerance?, curve_review? }`.
  - `by` is `parameters` (default), `curve`, `either` or `both`.
  - Parameter keys are allowed only when `by` uses parameters. `samples` and the curve keys are allowed, and `samples` required, only when `by` uses the curve. `samples` is 2 to 16 distinct integers in [-10, 10]. Curve distance is measured at those x values with exact rational evaluation.
  - A degenerate target is a malformed rubric: `quadratic` or `exponential` with `a = 0`, or `exponential` with `b = 1`.
  - Each `*_review` band must be strictly wider than its met band.
- Context (optional): `{ families?: Family[], ranges?: { <param name>: { minimum, maximum } } }`. `families` restricts which families the learner can pick. `ranges` is keyed by parameter name (`m`, `a`, `b`, `c`) and bounds every response and target parameter with that name. A response outside the context is `invalid`.
- Verdicts, in order: met per `by` (`either` is parameters or curve, `both` is parameters and curve) gives `met`. Within a review band gives `review/tolerance`. Different family with `by` using parameters gives `review/structure`. Otherwise `review/partial` if any parameter or sample is within the met allowance, else `review/value`. With `by: 'curve'`, a different family that traces the same sampled curve is `met`.

Pack scorer call:

```ts
import { gradeCurveParameters } from './v2AnswerShapes.js';

function scoreFit(payload: FitPayload, response: unknown, rubric?: unknown): V2Grade {
  const context = { families: payload.families, ranges: payload.slider_ranges };
  return shapeGradeAsV2Grade(gradeCurveParameters(response, rubric, context));
}
```

Rubric example (fit a parabola by sampled distance): `{ "family": "quadratic", "target": { "a": "1", "b": "0", "c": "0" }, "by": "curve", "samples": [-2, -1, 0, 1, 2], "curve_tolerance": { "absolute": "0.5" }, "curve_review": { "absolute": "1.5" } }`.

## 4. `arrangement.slots`

- Context (required, there is no open default): `{ pieceIds: string[1..64], slotIds: string[1..32], capacities?: { <slotId>: 1..32 }, repeatable?: boolean }`. Ids are unique and match the lesson id pattern `^[a-z0-9][a-z0-9._:-]{2,100}$`. Capacity defaults to 1 per slot. `repeatable` defaults to false, meaning a piece can be placed at most once across all slots. A missing or malformed context gives `invalid`.
- Response: `{ slots: { <slotId>: pieceId[] } }`. Array order is the order inside a slot. Unknown slot, unknown piece, over capacity, a duplicate piece when not repeatable, or zero placements is `invalid`.
- Rubric: `{ solutions: SlotMap[1..8], ordered?: boolean }`. Each solution is a full slot map under the same rules as a response. Any listed solution can be matched.
- Verdicts: grading takes the closest solution by multiset overlap. An exact match gives `met` (when `ordered` is true the in-slot sequence must also match). A right multiset in the wrong order, or the right pieces in the wrong slots with nothing missing or extra, gives `review/partial`. No shared placements gives `review/value`. Otherwise `miss`, `false_alarm` or `partial` per the aggregate convention.

Pack scorer call:

```ts
import { gradeArrangement } from './v2AnswerShapes.js';

function scoreSort(payload: SortPayload, response: unknown, rubric?: unknown): V2Grade {
  const context = { pieceIds: payload.pieces.map((piece) => piece.id), slotIds: payload.slots.map((slot) => slot.id), capacities: payload.capacities, repeatable: payload.repeatable };
  return shapeGradeAsV2Grade(gradeArrangement(response, rubric, context));
}
```

## Using the shapes in a pack

1. Declare the response and rubric schemas from the schemas module. `answerShapeResponseSchemas[shape]` and `answerShapeRubricSchemas[shape]` are strict structural schemas. `answerShapeRubric(shape, context)` additionally requires the semantic contract (for example a review band wider than the met band, or arrangement ids that exist in the context) by running the shape's sample builder in a `superRefine`.
2. In the pack scorer, derive the context from the pack payload only, never from the response, and return `shapeGradeAsV2Grade(gradeX(response, rubric, context))`.
3. For lesson validation, `answerShapeSample(shape, rubric, context)` returns a response that the same rubric grades `met`, or `null` for a malformed rubric. It fits the existing "scorer must not return `invalid` on the sample response" rule in `validateV2LessonForGrading`.
4. The browser and Forge import the generated copy. The browser result is advisory; Core's signed grade is authoritative.

Packs plug in through the aggregated pack-scorer lookup that the skeleton lane adds at the top of the grading dispatch. This piece adds no case to `gradeV2Response`, no `V2VisualKind` and no entry in the response or payload unions, so there is nothing to widen and nothing for the skeleton lane to merge against.

## Limits

| Limit | Value |
|---|---|
| Numeric text length | 32 characters, at most 15 integer digits and 12 decimal digits |
| Response points | 32 without a context, `maxPoints` up to 64 with one |
| Required or forbidden points | 32 each |
| Coordinate magnitude | 100000, 6 decimal places |
| Snap radius | 1000 |
| Curve samples | 2 to 16 integers in [-10, 10] |
| Arrangement pieces / slots / capacity / solutions | 64 / 32 / 32 / 8 |

Tolerances are percent-style in basis points (0 to 10000) and absolute decimals. Units are not modelled: a pack that shows units must convert before grading.

## Known limits and decisions

- Curve context ranges are keyed by parameter name only, not by family. A pack that offers two families with different slider ranges for the same name must validate that itself.
- A point response without a context is capped at 32 points. Packs with a board should always pass the box context.
- `by: 'parameters'` with a different family is `structure`, not `value`, so a pack can show a "pick the right kind of curve" cue.
- Samples are integers so evaluation stays exact. A pack that needs non-integer sample positions must scale its axis.
- An arrangement has no partial credit weighting. It reports only the closed diagnostic.
- Core-side zod schemas reject any own `__proto__` key explicitly, because zod 4 would otherwise silently drop it from the parsed output while the stored original keeps it.
