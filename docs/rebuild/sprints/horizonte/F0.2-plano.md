# F0.2 Plano: the shared SVG plane

Lane `plano` of Horizonte Visual. One reusable plane plus a pure TypeScript model. F1.9, F1.11, F1.12, F2.4, F2.5, F2.7,
F2.8, F2.10 and F2.17 draw on it instead of each writing their own SVG, scale, snapping and keyboard handling.

Status: implemented and unit-tested locally. Nothing here has been looked at in a browser, a screen reader or on a
touch device (see "Not verified").

## Files

All new, under `frontend/src/rebuild/learning/horizonte/plano/`:

| File | What it is |
|---|---|
| `model.ts` | The pure model. No DOM, no React. Every rule below lives here. |
| `model.test.ts` | 40 unit tests of the model. |
| `Plano.tsx` | The component: draws the layers, wires pointer and keyboard to the model. |
| `Plano.test.tsx` | 27 component tests (DOM, keyboard, pointer, table, copy budget, stylesheet). |
| `plano.css` | The styles: tokens and logical properties only. |
| `copy.ts` | The few words the plane owns, in en-US, es-MX and pt-BR. |
| `index.ts` | The public surface: `Plano`, `planoCopy`, and everything exported by `model.ts`. |

Nothing outside this folder and this document was touched. The `<pack>` folders, `registry.ts` and `harness/` belong
to the skeleton lane and were not created.

## Usage

```tsx
import { useState } from 'react';
import { Plano, type PlanoPoint } from '../plano';

export function PlaceOnLine() {
  const [point, setPoint] = useState<PlanoPoint>({ x: 2, y: 2 });
  return (
    <Plano
      label="Savings against weeks"
      summary="Savings start at 1 coin and grow by 2 each week."
      domain={{ xMin: 0, xMax: 10, yMin: 0, yMax: 12 }}
      xLabel="Weeks"
      yLabel="Coins"
      snap={1}
      tickStep={1}
      placeOnTap
      layers={{
        curves: [{ id: 'plan', label: 'Plan', fn: (x) => 2 * x + 1 }],
        handles: [{ id: 'you', label: 'Your point', caption: 'You', ...point }],
      }}
      onHandleChange={(_id, next) => setPoint(next)}
    />
  );
}
```

The plane is controlled. A handle shows the `x` and `y` its layer gives; a move calls `onHandleChange(id, point)` with
the point the model has already clamped, axis-locked and snapped. A board keeps the learner's answer in its own state,
and a board's scorer can call the same model functions (`resolvePoint`, `snapToStep`) to judge it.

## API

### `<Plano>` props

| Prop | Type | Meaning |
|---|---|---|
| `label` | `string` | The figure's name. Required. Board copy. |
| `summary` | `string?` | The takeaway in a sentence or two. Becomes the figure's description. |
| `domain` | `PlanoDomain` | `{ xMin, xMax, yMin, yMax }`. Required. A domain that cannot be drawn throws a `RangeError` at render. |
| `layers` | `PlanoLayers?` | What to draw (below). |
| `xLabel`, `yLabel` | `string?` | Axis names, written beside the axes. They also name x and y in announcements and the table. |
| `snap` | `number \| {x, y} \| null \| false` | Handles snap to multiples of the step, anchored at 0. Off by default. |
| `tickStep` | `number \| {x, y}` | Spacing of gridlines and numerals. Default: a nice 1, 2 or 5 step for about 6 (x) and 5 (y) intervals. Pass the snap step to draw the snap grid. |
| `keyStep` | `number \| {x, y}` | The fine arrow-key step. Default: the snap step, else a nice step of about a fiftieth of the span. |
| `digits` | `number` | Most decimals in announcements and the table. Default 2. |
| `size` | `PlanoSize` | The viewBox, default 600 by 400. Only its ratio shows. |
| `placeOnTap` | `boolean` | A tap or click on the plane moves the selected handle there, inside its limits. |
| `onHandleChange` | `(id, point) => void` | A handle asks to move. |
| `onPlaneTap` | `(point) => void` | A tap on the plane (not on a handle), clamped and snapped to the domain. For boards that add a point per tap. |
| `onActiveChange` | `(id) => void` | The learner picked another handle. |
| `copy` | `Partial<PlanoCopy>` | Overrides for the plane's own words. |
| `className` | `string?` | Added to the figure. |

### Layers

Every layer has a unique `id` within the plane and an optional `label` and `series` (`1` sky, `2` mint, `3` berry,
`'neutral'`). Polylines, curves and regions without a `series` take sky, mint and berry in drawing order (polylines,
then curves, then regions), so two layers are never the same colour by accident. Points default to series 1.
Handles default to the primary colour, which marks the thing being moved.

| Layer | Fields | Notes |
|---|---|---|
| `points` | `id, x, y, label?, series?` | A mark and an optional word beside it. Shape follows the series. |
| `polylines` | `id, points[], label?, series?` | Straight segments through the points. |
| `curves` | `id, fn(x), from?, to?, samples?, label?, series?` | Sampled from the callback (160 intervals by default, at most 600). The line breaks where the callback is not finite or jumps across the plot, so an asymptote is never joined. A callback that throws counts as not finite. |
| `regions` | `id, points[]` or `between: {upper, lower, from, to}`, `label?, series?` | A polygon, or the band between two bounds (each a constant or a function of x). |
| `handles` | `id, x, y, label, caption?, series?, axis?, bounds?, disabled?` | `label` is the accessible name. `caption` is a short visible tag. `axis: 'x' \| 'y'` locks a handle to one axis. `bounds` narrows its range inside the domain. |

### The model (`model.ts`, all exported)

- Domain and numbers: `domainProblem`, `clamp`, `decimalsOf`, `roundTo`, `niceStep`, `ticksAtStep`, `niceTicks`,
  `formatPlanoValue(value, locale, maxFractionDigits)`.
- Scale: `linearScale`, `createFrame(domain, size)` (domain to viewBox, viewBox to domain, and domain to a clamped
  percentage for the HTML layer), `clientToView`, `pointerToValue`.
- Snapping and limits: `stepFor`, `snapToStep`, `snapWithin`, `effectiveBounds`, `resolvePoint(raw, from, constraints)`.
  `resolvePoint` is the one rule every move goes through (pointer, tap and keyboard): lock the axis, clamp to the domain
  and the handle's bounds, snap to the grid without leaving those bounds.
- Keyboard: `resolveKeyStep`, `interpretKey(key, shift, point, config)`, `COARSE_FACTOR` (5).
- Words: `describePoint` ("x 3, y 4.5"; the separator becomes "; " in a locale with a decimal comma).
- Drawing: `sampleCurve`, `pathFromRuns`, `pathFromPoints`, `regionPolygon`, `regionCorners`, `assignSeries`.
- The table: `buildTableRows(layers, domain, xTicks)`. It reads the same layers the plane draws, so the picture and the
  table cannot disagree.
- Constants: `PLANO_VIEWBOX` (600 by 400), `HANDLE_HIT_PX` (64), `MAX_LINES` (60).

## How it behaves

- **Pointer.** A handle is a 64 px hit area (`var(--target-lg)`) around a 24 px disk. Dragging keeps the grab point (no
  jump to the pointer), uses pointer capture, and applies the model's rule on every move. Touch and mouse go through the
  same pointer events; the handle sets `touch-action: none`, the plot keeps `pan-y`.
- **Tap.** With `placeOnTap`, tapping the plane moves the selected handle. A tap that lands on a handle is ignored.
- **Keyboard.** Handles are `role="slider"` elements with a roving tabindex: the plane is one tab stop. Arrow keys move
  by the fine step, Shift by five times as much. Home and End jump to the lower and upper limit. Page Up and Page Down
  pick the previous and next enabled handle and move the focus there. On an axis-locked handle all four arrows run
  along its axis. Keys with Ctrl, Alt or Meta are left to the browser. Under snapping the fine step is always at least
  one grid step, so an arrow key always moves.
- **Announcements.** The handle's `aria-valuetext` carries the whole point ("x 3, y 4"), so a screen reader reads it as
  the learner moves. A separate polite live region announces "Label: x 4, y 4" after a key, a tap or the end of a drag
  (not on every pointer move), and appends "Limit reached" when a key cannot move the handle any further.
- **Show as table.** A plain button swaps the plane for a table of the same layers (handles, points, every polyline and
  region vertex, and each curve read at the x ticks) and back. The button changes its label ("Show as table", "Show
  graph") instead of using `aria-pressed`, which the recomposition gate keeps inside the design system. There is no
  switch when nothing is drawn.
- **Motion.** The only motion is a 250 ms glide of a handle after a key or a tap, declared under
  `prefers-reduced-motion: no-preference` and switched off while dragging. No spring, no celebration.
- **Size.** The SVG uses `preserveAspectRatio="none"` inside a box whose CSS `aspect-ratio` equals the viewBox ratio, so
  it scales from 375 to 1280 px without distortion. Strokes are non-scaling. Numerals, words, marks and handles are
  HTML placed by percentage, so they keep their size at any width.
- **Neutral board.** A surface, quiet `outline` gridlines, a 2 px `edge` axis through zero (or along the edge when zero
  is outside the domain), nothing decorative. Series use the strong sky, mint and berry tokens and always a second
  channel: a dash for lines (solid, `10 6`, `2 6`, neutral `6 3 1 3`), a pattern for regions (tint, stripes, dots) and a
  shape for points and handles (circle, square, diamond).
- **Words.** The plane owns only its own strings (`copy.ts`): the table switch, the table's first column header, three
  hints for keyboard users and the limit message. Everything else (figure name, takeaway, axis names, layer and handle
  names) is the board's copy. The hints are visually hidden and attached with `aria-describedby`.

## Not verified

These need a browser, a device or a person, and were not done in this lane:

- **Screen reader double speech.** A slider with `aria-valuetext` plus a live region is the documented pattern, but no
  real screen reader (NVDA, JAWS, VoiceOver, TalkBack) was run, so the two may read the same move twice. If they do,
  drop the live announcement for plain moves and keep it for "Limit reached".
- **Real pointer and touch.** Drag, pointer capture and tap were exercised with synthetic events in jsdom, which has no
  layout. Behaviour on a phone (a handle inside a scrolling page, `touch-action: none` against page scroll, edge swipes
  near the plot) is untested.
- **Visual check at 375 and 1280 px**, in light and dark themes: gutter width (set from the longest numeral in `ch`, not
  measured), numeral collisions on a crowded axis, pattern density (patterns are in viewBox units, so they scale with the
  plot), contrast of the series inks over the surface, and the focus ring against the series inks.
- **`prefers-reduced-motion` in a real browser.** The stylesheet is asserted to keep all motion inside the
  `no-preference` query; the glide itself was not watched.
- **Other languages in the layout.** Longer es-MX and pt-BR strings were checked against the Copy Budget only.
- **Right-to-left.** Not supported (see limits).

## Limits

- Two handles closer than 64 px have overlapping hit areas; the later one in `handles` order is on top. A board that
  needs close handles should keep them on different axes or use the keyboard to switch.
- The plane is left-to-right only: the frame forces `direction: ltr` so the x axis never mirrors.
- The table is read-only. It is the equivalent for reading, not a second way to edit.
- A two-dimensional handle is exposed as a one-dimensional `slider`: `aria-valuenow` is x (y for a handle locked to y)
  and the value text carries both coordinates. ARIA has no two-dimensional slider.
- The controlled model means a handle only moves if the board updates the props it passes back.
- Layer ids must be unique across the plane; they are React keys and table row ids.
- A handle at the edge of the domain has its 64 px hit area extend past the plot, over the gutter and numerals.
- Curves are resampled on every render (160 callback calls per curve). Keep callbacks cheap, or lower `samples`.
- At most 60 gridlines and ticks per axis: a finer `tickStep` is replaced by a nice step.
- A `between` region drops points where a bound is not finite, so a band across an asymptote can look cut.
- The snap grid is anchored at 0, not at `xMin` or `yMin`.

## Decisions made without asking

- **Controlled component.** Boards own the answer; the plane owns geometry and input.
- **HTML overlay for marks, handles and numerals.** SVG text and SVG circles would scale with the viewBox; the Bible
  wants fixed-size numerals, a 64 px target and words in HTML.
- **Page Up and Page Down pick the handle**, Tab stays one stop, so a board with several handles does not add several
  tab stops.
- **Keyboard step defaults to the snap step** (rounded up to a whole number of grid steps), so a key always moves.
- **`tickStep` is separate from `snap`.** A board that wants the snap grid on screen passes the same step to both.
- **es-MX and pt-BR hint strings are my own wording** (for example "Re Pág y Av Pág" for the Page keys in es-MX).
- **Lane setup note.** `scripts/setup-lane.ps1` could not run here ("running scripts is disabled on this system"). The
  execution policy was not changed; the steps were reproduced inline in the worktree.
