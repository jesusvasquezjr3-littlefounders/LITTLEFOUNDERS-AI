# W2 Lane 0: shells on real routes and the per-lane split

Status: in progress (implemented and locally verified; no acceptance or release approval is recorded). Recorded 26 September 2026 on branch `codex/spec-migration-s02`. Owner: Engineering (Lane 0) for implementation; the owner for the proposals below; Product for copy review; a named design reviewer for the visual review Frontend Bible 02 §12 asks for.

Wave 2 rebuilds the product's screens in six parallel lanes: (1) public site, sign-in, recovery, verification and onboarding, (2) learner home, courses, placement, territory, lessons and results, (3) the Mentor stage (Bible 08), (4) Family Hub, the Tutor's pages, tasks, banking and the teen wallet, (5) profile, social and settings, (6) the staff console. Lane 0 makes that possible: it mounts the shared shells of S03 on the real routes, removes the legacy chrome, and splits every file two lanes would otherwise both edit.

## Binding acceptance sources

- Owner decisions OD-2 (the frontend is rebuilt from scratch), OD-3 Option B (the self-registered teen's personal wallet; Tasks and approvals stay guardian-only), OD-4 (one design system, separate experiences), OD-6 ("Tutor" is only the verified parent; the learner's tab shows the chosen Mentor character's name and avatar), OD-15 (legacy UI destroyed, not restyled) in `product/13-OWNER-DECISION-LOG.md`.
- Frontend Bible 02 §1.1, rules 12, 13, 19–23, §7, §8, §9.7, §9.8; 03 §3.4 (thumb zone, sticky call to action); 06 (copy budget); 07 §4 (Mentor renders only from the real models); 08 §7 (the Mentor stage is one isolated component with a documented interface).
- The S03 record (`S03-DESIGN-SYSTEM.md`): its S03.5/S03.6 open items said the shells were never mounted on a real route with real session, entitlement and staff-grant data, and that the Tutor and staff shells were audited on the gallery only.

Risk classification: **frontend foundation and navigation**. Every signed-in page now renders inside a rebuilt shell, so a defect repeats on every route; the route guards were moved, so their strictness is a safety property.

## Implementation and rationale

**Routes (W2.0a).** `frontend/src/app-routes/` holds one module per lane: `site.tsx` (public pages; sign-in, recovery, verification and the OAuth landing; onboarding, account upgrade and the badge page), `learn.tsx`, `mentor.tsx`, `family.tsx`, `profile.tsx`, `staff.tsx` with `staffGrants.ts` (the one table of which grant opens which console page, read by both the guards and the staff navigation) and `core.tsx` (Lane 0: dev harnesses, `/account-suspended`, `/account-deletion`, the 404). `App.tsx` (now about 120 lines) only composes them and chooses each group's shell. All 59 paths were compared with the previous `App.tsx`; the lazy imports and every guard are unchanged (`RequireAuth`, `RequireAgeScreen` through it, `RequireOnboarded`, `RequireRole`, `RequireStaffPermission`, `RequireWalletAccess`, `RequireGuest`). React Router ranks routes by specificity, so order across modules does not matter; `/:handle` stays below every static path.

**Rebuilt copy (W2.0a).** The file is split into `rebuild-core` (design system, gallery, preview, shells, standalone states), `rebuild-site` (age screen, suspended account), `rebuild-learn`, `rebuild-mentor` (calibration and session surfaces), `rebuild-family` (social decisions, badge shares, achievement sharing, guardian invites), `rebuild-profile` (analytics choice, social tiers and requests, private profile, teen connections, profile safety, memory self-review, account deletion) and `rebuild-staff`. `i18n/rebuild.ts` registers the namespaces and merges them for the preview; each surface imports its own namespace's JSON, so a missing key is a type error. The i18n gate gained phase 1b (`agent/tools/check-rebuild-namespaces.mjs`): an unregistered or missing namespace, a top-level key in two namespaces (the merge would silently shadow one) and the old `rebuild.json` are refused. The asset gate, its mutation test, the glossary contract and the verify scripts read every namespace. `previewCopy.test.ts` became `rebuild/copy-budget/<namespace>.test.ts`, each exhaustive over its file's key groups (a key group added without a budget fails), with the same roles and age bands as before.

**Preview and audits (W2.0a).** `Preview.tsx` composes `preview/registry/<lane>.tsx`; a screen id may be registered once (`registry.test.ts`), unknown ids still fall back to the controls form. The audit composes `scripts/audits/lanes/<lane>.mjs`, each declaring its states, its synthetic-Core scenarios and the Core answers only its routes need; a state id or scenario declared twice refuses to load. The split kept the same 70 states and 12 scenarios before the new shell states were added.

**Shells on real routes (W2.0b).** `frontend/src/app-shell/` is the bridge between the application's providers and the rebuilt design system (it may read the auth context, the theme and Core; it imports no legacy UI component, 02 rule 23):

- `ShellRoot` mounts `RebuildRoot` and `RebuildProvider` with the application's language (i18n) and mode (`useTheme`), so tokens, dark mode and the container queries apply, and overlays open in the same mode and language.
- `AppShellLayout` renders `LearnerShell` for learners (a parent-created child, a teen, an adult, staff learning) and `TutorShell` for a verified parent (the `parent` role). The Mentor tab reads Core's `GET /tutor/preferences`: a character counts as chosen only when the learner has saved a preference (`personalized`); the tab then shows `MENTOR_NAMES[character]` and the manifest's real-model render; otherwise the word "Mentor" with no picture. The learner tab never says Tutor; the Tutor console has no Mentor slot.
- `StaffShellLayout` renders `/admin` in `StaffShell`; items are the staff slots, filtered by `permittedStaffItems` with the account's grants, superadmin-only sections only for a superadmin, then "Back to app".
- `SiteLayout` and `AuthLayout` render the public site (`SiteShell`: three page links, "Log in", one accent call to action, the docked call to action on the landing and family pages only, 03 §3.4) and the sign-in flow (`AuthShell`). The document title of a public page comes from the same table the build writes into each page's HTML for crawlers (`scripts/seo/site.mjs`, typed by `site.d.mts`), so the title a search engine renders is the one it was served.
- `StandaloneState` puts the 404, the suspended account and the deletion screen on `SingleStateScreen` (primary hue). The 404 is rebuilt from the design system's controls (the legacy one used legacy `Button` and `Icon`); the suspended and deletion surfaces render their content only (`KidSuspendedScreen`, `AccountDeletion layout="state"`).
- Kept from the legacy layouts, deliberately: the redirect of a suspended or deleted child to `/account-suspended`; the profile's language of record applied to the UI; the cookie preferences, legal links and contact address (site footer, via an exported `openCookiePreferences()` instead of the legacy button); the language and theme choices (site and sign-in footers, native select and segmented control); sign-out and the mode for signed-in accounts (a rebuilt panel in Settings, proposal 5).
- Removed: `AppLayout`, `navConfig.ts` (and its test), `MarketingLayout`, `AuthLayout`, the admin pages' `AdminSubnav`, and the unused legacy chrome copy (`dashboard.nav.tutor` "AI Tutor"/"Tutor IA", the locked-item hints, the sidebar and upgrade-panel strings). `APP_HOME` moved to `app-shell/home.ts`.

**Legacy page bodies inside the shells.** Until its lane rebuilds it, a legacy page body renders inside the shell's `<main>` in `LegacyBody` (`[data-legacy-body]`), which restores the legacy typography and the content box the legacy layouts gave it (the shell hands it the whole content area). The design system's element rules (`h1`, `h2`, `p`, form-control font and focus, link focus, the site's display `h1`) now skip that subtree and apply again to a rebuilt root nested inside it; `:where()` keeps each selector's specificity exactly as before. The audits skip the legacy body the same way (`in-page.mjs`), so they measure the shells and every rebuilt panel, never legacy copy. Nothing in the legacy pages used an outlet context. `verify:app-shells` asserts that no legacy chrome is left outside the body.

**Defects found on the real routes and fixed.**

- *Route focus on first load.* The shells' `useRouteFocus` used a "first render" flag; React's development StrictMode runs effects twice on mount, so the first load was treated as a route change and focused the `<h1>`, and the first Tab then skipped the skip link. It now compares against the last settled route key (a StrictMode regression test, mutation-checked).
- *Route focus lost on navigation.* Because `RequireAgeScreen` remounts the page on every new path, the shell never saw its key change. The gate must stay that strict, so `ShellRoot` remembers the last path a shell showed and treats a mount on a different path as the route change it is (scroll to the top, focus the new `<h1>` or `<main>`); the first load of the app moves nothing.
- *Tab bar wrapping in Spanish and Portuguese.* With five tabs at 375 px ("Aprender", the Mentor, "Tareas", "Cartera", "Perfil"), the learner tab bar wrapped onto two rows. The tab link's inline padding is now one spacing step instead of two (the 8 px gap between targets is kept).
- *Main under a sticky header.* Focusing `<main>` (skip link, route focus) scrolled its start under the site header and the console app bar; `<main>` now has a scroll margin of the header's height.

**Navigation (W2.0c).** `app-shell/navigation.ts` defines one navigation per shell as slots (id, copy key, path, owning lane). A lane changes only its slot's `path`; adding, removing or reordering slots is Lane 0's. Unit tests pin every population's items, the staff items against the route guards for every grant combination, the current slot of a path and the OD-6 wording.

**Mentor stage boundary (W2.0d).** `check-product-spec.mjs` now lists the stage bridges by name (`STAGE_BRIDGES`): `rebuild/learning/CompactMentorStage.tsx` (unchanged) and `rebuild/mentor/MentorStage.tsx`, reserved for the Mentor lane's one isolated stage component (08 §7); it may not exist yet. Only the same three targets are allowed (the 3D renderer, its quality probe, the theme context). No directory is opened: any other file of `rebuild/mentor/`, a nested `MentorStage.tsx`, a legacy UI component or a `tutor/` session hook from the bridge is refused (mutation tests). The `tutor/` hooks were not moved.

## Decisions taken on the SPEC's conservative default (proposals for owner review)

1. **Learner navigation order**: Learn, the Mentor (second, as the mockup), then Tasks, Wallet, Profile. A parent-created child's coin card (`/banking`) is labelled "Wallet"; a teen who linked a verified parent sees their personal Wallet and the family coin card as "Family coins" (six entries: the one population whose phone tab bar can wrap).
2. **Hidden, never locked**: the legacy menu showed Tasks, Banking and Family locked for people who could not open them. The shells hide them (S03's "navigation hides what a person cannot open"). An adult who is not a verified parent gets one "Become a Tutor" entry to `/verify-parent` instead (never shown to a staff account, a child or a teen).
3. **The verified parent's shell**: a parent gets the Tutor console on every signed-in page, including their own learning: Family, Tasks, Coins, Learn, Profile (no Mentor slot, per S03's shell contract). Whether a parent who learns should see the learner shell while learning is an owner decision.
4. **Staff**: the console lists Overview, Content, Users, Emails, Analytics & Health, Learning intel, Generation, Audit log, Reports, Roles & Access (superadmin only), then "Back to app". A staff account's learner or Tutor shell carries a "Staff" entry. Insights is not a separate entry: its route only redirects into Learning intel (G.5; the S09.3 note should say so).
5. **Sign-out and the mode in the app**: the legacy sidebar held sign-out, the theme toggle and a language dropdown. The rebuilt learner and console shells have no slot for them, so they moved to Settings, where the language already was: a rebuilt panel ("On this device": the mode as a three-way choice, and "Sign out") mounted by Lane 0 in the legacy Settings page (`app-shell/SessionPreferencesSetting.tsx`, `rebuild/shell/SessionPreferences.tsx`). From the staff console it is two steps away ("Back to app", then Profile). The owner may prefer a shell slot instead.
6. **Public site**: the language and theme choices moved from the header to the footer (the mockup draws them in the header; the rebuilt site header has no slot for them); the header's primary call to action is "Sign up" for visitors and "Open app" for a signed-in visitor (a guest included), as before.
7. **Sign-in shell**: `/verify-parent` and the OAuth landing moved from the marketing chrome to the sign-in shell (they are trust-surface steps of the sign-in flow); "Home" (or "Open app" when signed in) is the shell's way back.
8. **Standalone states** use the primary hue.
