## Implementation and rationale

### W2L.1: the home (L1), the course (L2), the journal and the rhythm

**Data (course.ts, learnHome.ts).** `fetchShelf` validates `GET /learn/courses` (the B.6 `pathway` field and B.3 `unavailableFeaturedCourse` included); a malformed shelf is unavailable, never partly shown. `fetchCourse` asks for the pathway (`/path`) first and reads the tree only when Core answers `PATHWAY_ENGINE_DISABLED`, so the one screen follows whichever engine Core runs; every refusal (`COURSE_AGE_RESTRICTED`, `COURSE_PREREQUISITE_REQUIRED` with its slugs, `NOT_FOUND`, a lost connection, a refusal, anything else) has its own state. `nextStep` reads what Core computed (the recommended frontier item, the tree's `nextLessonId`, the placement flag, completion); nothing re-derives a lock and no age reaches the client. The host transport reports a request that never arrived as `NETWORK`, so a page can say "offline" rather than "unavailable".

**L1, the home (LearnHomeView).** A dashboard (02 rule 15, `DashboardLayout` 7:5 from an 840 px container). The greeting is the `<h1>` (headline size, as the mockup: it is not the point of the page). The primary column leads with the featured course's next step as the page's one accent call to action: the recommended lesson opened directly with the course to return to, "Start" under "Find your start" when a placement is owed, "Review" when finished; without the course's own read, the shelf's B.6 recommendation still opens the lesson. Then the shelf: one identity card per course (hue, own icon, title; 02 §4.3) with its progress or lesson count and one link in. A course the age safeguard closes keeps no hue and no link and says it opens later. B.3's unavailable featured course is an info banner naming it, with a retry. The secondary column holds the streak (the run, the rest days left, the best streak kept in view while it rests, a link to the rhythm where the learner's own pace is set; the "resting" state never says lost) and the learner's story (the journal link, and an independent teen's self prompts where they are). The graduation card (B.23) appears above when owed. The page reads Core's register for its Copy Budget band (`data-age-band`; the youngest while unknown). Stale-while-revalidate on the shelf is kept from the legacy page.

**L2, the course (CourseView).** One screen, both engines: the back link to all courses and the map, the course title and progress, the in-progress notice, then the next step (placement, recommended lesson with its minutes, or a plainly stated finished path, never celebrated here), then, under the pathway engine, the other open lessons as real choices (B.24; layered: two for a child, four otherwise), the chapters with their access (closed ones counted, never listed) and the skills; under the linear engine, the chapters start closed (the next lesson is the hero's) and each opens to its lessons in Core's order (done with the kept best score, next, open, later; a placement credit never shows a score it did not earn). The placement is offered rather than forced (the legacy redirect sent a learner into a quiz without a word); every lesson endpoint still refuses until it is taken. The top row and the `<h1>` are the same DOM elements in every state, because the shell focuses the heading on arrival while the course is still loading.

**Shell integration.** A rebuilt learner page is its own design-system root (`.lf-rebuild.lf-learner-page`) inside the shell's page slot, which still wraps every route in the legacy body box. `learnerPage.css` hands such a page the whole slot and gives it the shell's own content padding (keyed on the lane's class, no Lane 0 file changed for it). The pages render no `<main>`: the shell's is the only one.

**Assets.** Three own course icons in the house style, registered as drafts in the manifest (`course.first-steps.icon`, `course.business.icon`, `course.investing.icon`; `course.money-basics.icon` existed): plain shapes, token colours, at most three hues, no accent or error. The home's streak uses the existing flame asset. No stock icon, no glyph added (19 of 24 families).

**Removed legacy.** The deleted files were proven unreferenced by grep (the dev learn lab now mounts the rebuilt hosts). Their CSS classes that nothing renders any more (`lf-chip-success`, `lf-now`, `lf-live-dot`) were removed from `index.css` and from the design-class gate's required list, which the gate demanded.

**Shared files touched (minimal, reported to Lane 0).** `src/index.css` (the three dead legacy classes above), `src/__tests__/designClasses.test.ts` (the same two names out of its required list), `scripts/audits/lanes/core.mjs` (its blanket empty `/learn/courses` answer now yields to a scenario that declares its own shelf), `scripts/audit-rebuild.mjs` (the first-paint wait reads `AUDIT_READY_TRIES`, default unchanged at 15 s, because the audit could not finish on the shared machine), `frontend/package.json` (the `verify:learn-pages` script).

### W2L.2: the course world (L3) and the placement flow (L4)

**What the legacy screens did (found 26 September 2026).** `/learn/:courseSlug/territory` rendered the legacy `TerritoryPage`: adventure cards (Material icons, a lock glyph for locked adventures), saga columns of topic chips linked to their first playable lesson, a legend of the four topic states and a progress strip; no scene art at all (the six themed scene components in `routes/app/learn/scenes/` were last used by the adventure banner W2L.1 deleted). `/learn/:courseSlug/placement` rendered the legacy `PlacementPage` inside `GuidedStage`: a fixed cast of characters per line (Dr. Rho, Liruf, Dina, Zara) speaking pre-generated voice clips, a legacy option group, legacy buttons, and a result screen that showed the count of skipped lessons and "Topic n of N" beside the S05.3d framing line.

**Data (territory.ts, placementFlow.ts).** The map reads `GET /learn/courses/:slug/tree`, which Core serves under both engines (with `pathwayAccess` per chapter under the pathway engine), validated by a zod schema (a malformed tree is unavailable, never partly drawn) and refused exactly as the course screen's entry (`courseRefusal`, now exported from `course.ts`). The flow keeps Core's stateless contract: the whole answer history on every `POST /step`, nothing written before `POST /commit`, the identical body on a retry, `PLACEMENT_ALREADY_COMPLETE` treated as "a start is stored" (the learner opens the course), `COURSE_AGE_RESTRICTED`, `NOT_FOUND` and refusals as their own states. "I don't know yet" is sent as one index past the last option, as before; "A bit earlier" sends `floor(frontier x 0.6)`, which Core clamps downward only.

**L3, the course world (TerritoryMapView).** A neutral page with coloured cards (02 rule 15). Each chapter is a world card led by its scene art (B.8's "territory map's thematic immersion", our own SVG per theme, 10:3, decorative because the chapter name beside it is the heading). The world holding the next lesson takes the soft primary well and a solid "You are here" tag; a finished world says "Done"; a world not reached shows its name and "Later" only, with no scene and nothing to open; an extra (younger) chapter says "Extra"; a chapter closed by age is counted in one line and never listed. A world opens to its topics (the shared List and ListRow under saga headings); each topic says its state in a word (next step, review, done, started, opens later) and opens the next, an open, or a passed lesson with the course to return to. The reviews-due count sits under the progress as a pill. When the placement is owed the map leads with "Find your start" and no topic is pressable. The legend was cut (layering, 06 §4: each state is named where it appears), and the Diorama is not used here: 02 rule 10 reserves simulated 3D for the Mentor characters and their Diorama, and 08 places the Diorama on the Mentor stage and the lesson's compact band (where "the band may show the active adventure's scene": these scene assets are the natural source for that band, a later checkpoint).

**L4, the placement flow (PlacementFlowView).** A full-screen layer like the lesson player (no app navigation), on Lane 0's `StandaloneState` single-state screen in the sky hue (02 rule 15; the outcome view already used sky in S05.3d). One step at a time: a bar with the close control (and "Back" on a question after the first), the step's heading, at most one Mentor turn (the learner's own chosen character as a real-model render with its name; no character and no stand-in before one is chosen, 02 rule 21), and the step's actions with one accent. Questions are the shared `AnswerChoice` on surface cards; pressing one answers (no verdict is ever shown). The outcome is `PlacementOutcomeBody` (split out of `PlacementOutcomeView` so the flow mounts it inside its own screen): Core's closed frame, the prior-exposure line and either the growth line or, when Core stopped the start before a topic with an unmet prerequisite, "The next topic needs a new skill." The learner's adjustment offers "A bit earlier", "From the beginning" and "Keep this start". A failed step or save keeps the screen and says so in one line; the learner's own action (the answer, "Start here", "A bit earlier") sends the same request again, the identical body for a save (B.1), so there is no second retry control, and while that line shows the outcome keeps only its prior-exposure line (the first view stays within 06 §3.1 for the youngest). Focus moves to each new step's heading when the learner moved the flow; arrival stays the shell's (the heading is one element from loading to the first step, so the shell's focus survives the answer).

**Assets.** Six own scene assets registered as drafts (`scene.archipelago.art`, `scene.forest.art`, `scene.city.art`, `scene.valley.art`, `scene.kingdom.art`, `scene.cosmos.art`; slot `adventure.scene`, 10:3, family `scenes`): plain shapes in token colours, at most three hues each, no accent or error red, no text, 1 to 2 KB. They are the first assets of the `scenes` family, so the owner's style review applies (07 §7 item 2). No glyph added (19 of 24 families). The Mentor renders are the existing avatar renders.

**Shared files touched.** Only the shared asset manifest (`src/rebuild/assets/manifest.json`), where the six scene rows were added (07 §6: every own asset is registered in the manifest). No Lane 0 shell, control or route-composition file changed: the flow uses Lane 0's `StandaloneState` and `useMentorCharacter` as they are. The shared `assetGate.test.ts` was measured, not changed (see the limitations).

## Decisions taken on the SPEC's conservative default (proposals for owner review)

W2L.1:

1. **Course identity slots.** The four published courses take the four identity slots of 02 §4.3: `first-lemonade-stand` first steps (primary, sprout), `financial-education` money basics (mint, coin), `entrepreneurship` start a business (berry, rocket), `investing` smart investing (sky, chart). A future course with no slot gets a neutral card and no icon. The three new icons are drafts awaiting the owner's style review (07 §7).
2. **Placement offered, not forced.** The course screen shows "Find your start" with its one-line framing instead of redirecting into the quiz; lessons stay closed by Core until it is taken.
3. **Catalog titles' copy role.** Course, chapter, topic and lesson titles are budgeted by the role of the element they sit in (`heading` for the page and hero titles, `option` for rows), as S05.3b did; they are content authored in Forge, whose own gates budget them.
4. **The legacy track filter is not rebuilt.** It showed only above six courses and the catalog has four; it will return when the catalog grows, as a design-system chip filter.
5. **The home's hero and the shelf both list the featured course.** The hero is the next step, the shelf is the catalogue; the mockup shows both.
6. **Lesson rows without minutes and XP, chapters without topic subheadings** (see "Legacy details not carried over" below): the conservative reading of the register policy (B.20, B.23: coins and XP sparing for the young, on the result) and of the Copy Budget's first view.
7. **Layering to fit the first view (06 §3.1, found by the copy-budget audit).** The home keeps the streak and its rest days and links the pace (on the rhythm, one press away) instead of repeating it; the story card is its heading and the journal link; the course screen's chapters start closed (the legacy page opened the chapter holding the next lesson), the hero has no "Start here" kicker, an open chapter carries no tag, the disclosure is one word ("Lessons", its state said by `aria-expanded`), and the placement's action is "Start" under the heading "Find your start" (no repeated words).

W2L.2:

8. **The placement is silent until its lines are voiced again.** The legacy flow played pre-generated clips of a fixed cast (Dr. Rho, Liruf, Dina, Zara by line). Those lines break the Copy Budget (up to 30 words against the Mentor's 12 to 20) and 02 rule 16 (an em dash), two of them carry the verdict language B.15 removes, and a fixed cast contradicts OD-6 and OD-19 (the learner's own chosen Mentor). The guided-voice drift guard refuses a clip whose text differs from the caption, and regenerating clips is a paid call (OD-23), so the rebuilt flow shows the new short Mentor turns as captions only. Proposal: the owner runs the voice generation for the new placement turns in each of the four characters' voices, and the flow plays the chosen character's clip (the caption stays, 08 §5).
9. **The outcome shows Core's frame only.** The legacy result also showed "We're skipping N lessons" and "Topic n of N". B.15 (S05.3d) framed the outcome as the closed frame with no count; the course screen and the map show the credited lessons as done. The prerequisite stop is kept as its own plain line.
10. **The placement is a full-screen sky layer, not a learner-shell page.** It is one state at a time (02 rule 15) and was a full-screen layer before; closing it opens the course, where nothing is lost (nothing is stored until a start is chosen).
11. **The map opens worlds on request.** The legacy map listed every topic of every unlocked adventure at once; the first view now carries the worlds and "you are here" (06 §3.1), each world one press from its topics. The topic-state legend is cut: each state is said where it appears.
12. **Scene art per chapter theme, not the Diorama.** The six themes are drawn as flat own assets; the 3D Diorama stays the Mentor's (02 rule 10, 08).
13. **"Back" in Spanish is "Regresar".** "Atrás" is also a verdict word ("behind") in the B.15 lexicon the copy test runs over the placement strings.

## Remaining limitations and open items

- **Evidence scope.** Chromium only, local, against a synthetic Core; no real Core, database or provider was contacted (OD-23). Safari, Firefox, device and screen-reader passes (02 §12) and human design review are not done. Nothing here is accepted or released; the `REQUIREMENTS.md` rows touched (B.2, B.3, B.6, B.9, B.21, B.23, B.24 in W2L.1; B.1, B.8, B.15 in W2L.2) record the wave-2 composition as locally verified and stay "In progress".
- **Not in this checkpoint.** The lesson player's frame and the result screen are later checkpoints of this lane. The lesson player is still the legacy one: the placement flow and the map hand it the lesson with the course to return to (`courseSlug` in the route state), which it already reads. The lesson's compact Mentor band does not show the chapter's scene yet (B.8 inheritance, 08 §11); the scene assets made here are its natural source.
- **Legacy details not carried over, deliberately.** Each lesson row's "minutes and XP" line (the register policy puts coins and XP on the result, sparingly for the young; the next step still says its minutes); the saga and topic subheadings inside a chapter (the rows follow Core's order; the topic structure is the territory map's); the floating "Go to my lesson" pill and its auto-scroll (the next step is the first thing on the page); the raster course badge art on the shelf (the course identity icons replace it; badges stay on the profile); the six-course track filter (never rendered with four courses). Proposals 4 and 6.
- **A rebuilt page inside the legacy body box.** The shell still wraps every route in `LegacyBody`; `learnerPage.css` hands a rebuilt learner page the whole slot by a rule keyed on the lane's own class. A shell-level slot for rebuilt pages (Lane 0) would remove the rule; requested, not built here.
- **Long chapters.** Under the linear engine an open chapter lists every lesson (a published chapter holds up to about 60), as the legacy accordion did; there is no virtualisation.
- **The featured course's read is the whole tree** under the linear engine (as the legacy home's), on top of the shelf; `/learn/courses` itself is slow by design debt (it builds every course tree). Unchanged here.
- **Draft assets in product use.** The three new course icons, the six chapter scenes (the first assets of the `scenes` family, so the family's style review applies, 07 §7 item 2) and the Mentor avatars are drafts awaiting the owner's style review; a release build refuses drafts by design.
- **Machine load.** The final unit-gate run and the browser runs shared the machine with five other lanes; the test files that timed out under that load passed when rerun alone (see the log), and the matrix needed a 60 s first-paint wait.
- **The vitest worker RPC timeout and the asset-gate test (S03, shared).** The quiet run this checkpoint asked for was done (26 September 2026, CPU at 9% before it): the lane's 42 test files passed and the run still ended with `Timeout calling "onTaskUpdate"`, so machine load is refuted as its sole cause; the same lane files without `assetGate.test.ts` (40 files, 326 tests) ended with no RPC timeout. The cause is the shared `src/rebuild/assets/assetGate.test.ts`: each case copies the rebuilt tree into a temporary directory and runs the gate with `spawnSync` five or six times without yielding, blocking its worker for longer than vitest's RPC timeout. Measured: the gate takes 0.4 to 2.9 s on the source tree and 3.5 to 9.3 s on a freshly copied tree, and one copy took 20 s (file I/O on new files, not CPU). Alone, the file took 273 s and one case passed its 90 s limit. The test is Lane 0/S03-owned and was not changed here; the proposed fix (`execFile` and `fs.promises.cp` so the worker keeps answering, or a longer per-case limit) is listed for the orchestrator. Every assertion in it passed in the lane-scoped run.
