## Implementation and rationale

**Where things live.** `frontend/src/rebuild/staff/console/`: `staffConsoleApi.ts` (hand-mirrored wire shapes with arrival shape checks, the `StaffApi` interface, `useStaffRead`, `staffViewer`), `staffConsoleCopy.ts`, `ConsoleParts.tsx` (page frame, metrics, facts, load failure, pager, copy-id, share bars), `DailyChart.tsx`, one file per screen, `staffConsole.css`, and `staffConsoleFixtures.{json,ts}` (the preview and the audit's synthetic Core answer from the same JSON). The rebuilt files import nothing outside `src/rebuild` and `src/i18n` (`spec:check` boundary): the route hosts in `frontend/src/app-routes/staffConsole.tsx` hand them Core (the app's own client, the staff member's session token; a failed fetch while the browser is offline becomes `OFFLINE`) and the grants from the auth context. `app-routes/staff.tsx` lazy-loads the hosts for the six sections; `app-routes/staffGrants.ts` marks them `rebuilt` and exports `isRebuiltStaffPath`.

**Grants.** `staffViewer` reads grants as Core's `requireAdminPermission` does: only an admin's named grants count and a superadmin holds all. The Overview's section list mirrors `STAFF_ROUTE_GRANTS` (pinned by `app-routes/__tests__/staffConsole.test.tsx`). A section the viewer cannot open is neither linked nor requested; a direct link is refused by the unchanged route guard (verified: no console read happens). A read refused by Core with 403 (a grant withdrawn after the page opened) shows "No access to this" with a retry.

**Overview S1.** Legacy: six KPI tiles, a quick-actions grid with one-line descriptions, content status bars, a role distribution, retention buckets and weakest topics, a health strip. Rebuilt: the same content by grant; the metrics say words plus numbers; content status as labelled share bars with the count and share written; the review queue as a notice with a "Review lessons" link; service health says "Every service answers" or how many do not, and each monitor carries a glyph and a word (02 rule 6); "Health monitoring is not set up here" when Core answers `PULSE_UNCONFIGURED`. Section links use the staff navigation's own labels (`rebuild-core.json`), so a page title and its menu entry never differ.

**Users S3 (A.5).** Legacy: KPI tiles, a funnel card, role/locale/age distributions, a recharts signup timeline with range presets and a daily/cumulative switch, search and role chips, a table, a detail dialog with the revoke form. Rebuilt with every capability kept: the funnel card is shown and requested only with `view_analytics` (the legacy card asked for it with any grant and hid a 403); the signup timeline is our own single-series bar chart (one hue, average rule, period and metric as segmented controls, total/average/peak/change written as text, a readout of the hovered or latest day) instead of recharts' gradient area; the table collapses to cards below 840 px; the details sheet puts the person's name, then parent verification (status chip; reason field; revoke behind a keep-first confirmation naming the person), then the read-only facts with "Copy ID".

**Roles & Access S10.** Legacy: KPI tiles, role distribution with last change, a review-due count, a grant form (user id, role dropdown, justification for Tutor), a candidate search dialog, a holders table with inline revoke chips and a manage-access dialog with permission switches and assignment history. Rebuilt: the G.4 card now lists each due grant (person, role, grant date) with a "Manage" button instead of a bare count; the grant form checks the id shape before calling Core and names the database's refusal (`ROLE_REJECTED`); the holder sheet holds roles (each removal confirmed), staff-grant switches (the design system's `Switch`, state in words) and the grant history (roles and staff grants, who granted, when).

**Audit log S9.** Legacy filtered by action only (from the loaded page) plus a client search. Rebuilt: action, actor id (checked as a full UUID), subject and a date range go to Core's `AuditQuerySchema` (exact matches, inclusive days) from a filters sheet; an active-filter notice shows how many are on with "Clear filters"; the page search still narrows only the loaded page; server paging with the range in words; the detail sheet says the record cannot be changed and shows the JSON detail wrapped, never scrolled sideways.

**Reports (E.3).** Legacy: a table and a detail dialog with Resolve. Rebuilt: open/pattern/open-report counts, a status filter, origin and status as glyph-plus-word chips, the case sheet with each report's category, date, short reporter id and capped note, a note for automatic pattern cases, and Resolve behind a confirmation that says the decision goes to the audit log. The queue now asks Core for its full page (limit 200; the legacy page used the default 50).

**Emails S4.** Legacy: six KPI tiles, a recharts trend, status/template/locale breakdowns, search and dropdown filters on the server, a table with a separate phone card list, a detail dialog, a refresh action, a partial-failure card. Rebuilt with the same capabilities: the history is one `DataTable` (cards below 840 px), the search is debounced (300 ms) before it reaches Core, the totals and the history fail and retry separately.

**Shared decisions.** Every string is in `rebuild-staff.json` → `staffConsole`, keyed `<screen>.<role>.<key>`, so the copy-budget test reads each string's role from its path and fills placeholders with the longest real value. Role names: Superadmin, Admin, Bigfounder, Tutor (the `parent` role, OD-6), Child, Universal. No character, no celebration, no motion of our own; system glyphs only (check, cross, info, warning, chevron, close); tokens only, light and dark; 48 px targets; layout by container width (metrics balance their rows by their own container: no orphan tile).

**Defect found on the real route and fixed in the design system (Lane 0 file, minimal).** On `/admin/reports` a real press on "Open" opened the case sheet but focus fell to `<body>` while the page behind was already inert: under React's development double effects, `useLayerHost` appended a host, removed it and appended a second one, and a render still holding the first (removed) host ran the focus trap there. `rebuild/design/overlays.tsx` `useModal` now treats a disconnected host as not ready (one line). Pinned by a StrictMode test in `StaffConsole.test.tsx` that fails without the fix and passes with it; the users, audit and email sheets had passed by timing only.

**Removed legacy files** (this lane's own route files; nothing else imported them, proved by `git grep`): `routes/admin/AdminOverviewPage.tsx`, `AdminUsersPage.tsx`, `AdminRolesPage.tsx`, `AdminAuditPage.tsx`, `AdminReportsPage.tsx`, `AdminEmailDashboard.tsx`, `UsersFunnelCard.tsx`, `SignupTimeline.tsx`, `adminNav.ts`, and their tests (`AdminOverviewPermissions`, `AdminUsersPage`, `AdminGovernancePages`, `AdminEmailDashboard`, `SignupTimeline`), whose assertions are carried by the new tests. `adminPermissions.test.tsx` now derives the visible sections from the staff shell's navigation instead of `adminNav.ts`; its guard assertions are unchanged. `adminShared.tsx` stays (the legacy Content, Generation, Intel and Analytics pages still use it).

**Changes outside the lane's files (Lane 0 or shared), each minimal:**

1. `app-shell/AppLayouts.tsx` `StaffShellLayout`: a rebuilt console path renders its screen directly in the shell's content area; every other path keeps `LegacyBody` (one conditional, reading `isRebuiltStaffPath` from this lane's `staffGrants.ts`).
2. `rebuild/design/overlays.tsx` `useModal`: the host race fix above.
3. `frontend/package.json`: the `verify:staff-console` script.
4. `frontend/scripts/audit-rebuild.mjs`: an optional `AUDIT_READY_MS` (default 15000, unchanged behaviour) for how long a state may take to become ready; needed because the shared machine was saturated (see the log).

## W2T.2: implementation and rationale

**Where things live.** `frontend/src/rebuild/staff/console/`: `contentApi.ts` and `generationApi.ts` (hand-mirrored wire shapes with arrival checks, the release-refusal map, the anomaly rules, the Realtime row mapping), `StaffContent.tsx`, `StaffGeneration.tsx`, `StaffMentorQuality.tsx`, `SeriesChart.tsx` (one series over ordered points, and judge scores as labelled bars), and `staffSectionFixtures.json` (the preview and the audit's synthetic Core answer from it). The route hosts are in `app-routes/staffConsole.tsx`; the Realtime feed in `app-routes/staffLiveFeed.ts`. The C.5 / C.6 panels (`rebuild/mentor/LiveContentGovernance.tsx`, Lane 3's file, not edited) and the C.24 dashboard (`rebuild/staff/MentorQualityDashboard.tsx`) are mounted as built in S06.12 / S06.13, with data from the console's own Core client instead of their stand-alone token clients.

**Content S2.** Legacy: six KPI tiles, the B.3 alert card, four tabs (Courses; Lesson Review Queue; Tutor Live Review; Learning Quality), a course dialog with Publish / Unpublish / Archive and no confirmation, a lesson dialog with the legacy lesson player, component, media and JSON tabs, and Approve / Reject; a live-review list with Approve / Reject and a JSON disclosure. Rebuilt with every capability kept:
- **B.3** heads the page in every view as a quiet error notice plus a list (course, how many times, when last), because a dropped course is an operational fault, not a view. An older Core without the list reads as none recorded; a malformed list is an error state.
- **G.2**: the course sheet puts the release note ("Publishing runs the release check first. There is no direct publish.") and the decision directly under the title. Every status change goes through a keep-first confirmation (the legacy page published on a single press); archiving is the destructive one. Each Core refusal code has its own sentence and next step (`RELEASE_NOT_FOUND`, `_ARCHIVED`, `_INCOMPLETE_HIERARCHY`, `_LESSONS_NOT_REVIEWABLE`, `_INCOMPLETE_LOCALES`, `_VERIFICATION_REQUIRED`, `_VERIFICATION_INCOMPLETE`, `_COURSE_RELEASE_REQUIRED`, and `_BLOCKED` for any other `RELEASE_*`); an outage says it did not save. The same states apply to a lesson's Approve (`release_lesson`).
- **Lesson review**: the sheet shows what the lesson is, then the decision, then the inspector (language switch; Preview, Parts with linked audio and JSON, Media with audio players and images with a full-size link, Data with the client-safe document), then the remaining facts. The preview is the learner's own lesson player (see the bridge below). After a decision the queue re-reads when the sheet closes; focus returns to the queue section if the row it came from is gone.
- **Mentor activities (C.5, C.6, G.3)**: the S06.12 status panel and the pack release side by side from 840 px, and the sampled queue below. The activity sheet shows the type, the topic type Core stamped on the item (`provenance.risk_category`; an item sampled before S06.12 says "Not recorded" rather than guessing), when it was served, the learner's score, what the learner saw, three equal verdicts (approve, a quality issue, a safety issue) with the audit-log note, and the answer key and raw data. The queue is re-composed from the S06.12 copy and `reviewBody` instead of mounting `LiveReviewDecision` once per row: that component reviews one item and must name a category, which an older item does not have.
- **Learning quality**: the S05.3d panel, reading and writing through the console's client; its own states are unchanged.

**Generation S7.** Legacy: four tabs (Live Monitor with a React Flow canvas and Supabase Realtime, Run History with tracks, run inspector, timeline, compare and a slot modal, Analytics, Coach) and an alert banner. Rebuilt with the same reads and every figure written as text:
- **Live**: Core is polled every 4 s; the route host adds the Realtime feed where the public Supabase variables exist. The transport line says which is working ("Checks every few seconds", "Live updates are on", "Live updates failed. It still checks every few seconds.", "Live status did not load. It keeps trying."). The React Flow canvas is replaced by the same per-stage counts as an ordered list with a state word (Waiting, Working, Done) and no pulsing motion.
- **Alerts**: the legacy thresholds are kept (a projected cost over $100, cache hits under 20% after 100k tokens, more than 30% of more than 5 lessons failed; across runs, a safety, age-fit or concreteness drop over 0.8, and a cost per lesson above twice the average). **Defect found in the legacy page and fixed:** Core lists runs newest first (`order=updated_at.desc`), but the legacy banner and "latest run" quality card read the end of the list, so they compared the two oldest runs. The rebuilt rules read the first entries; charts reverse the list to read left to right in time. Pinned by a unit test.
- **Run history**: tracks (a halted one shows Core's reason), the run selector, the run's counts, failures by stage, judge means, time per lesson, the lessons table (cards below 840 px) with a lesson sheet, the heartbeat timeline (progress, cost, and one small multiple per working stage), and a two-run comparison that asks Core only when two different runs are chosen.
- **Trends and Coach**: the averages, the historical alerts, cost and cache trends, the success rate, the forecast, the latest run's judge scores and failures by stage; the Coach's outcomes, failures, recurring errors, judge scores with their minimum, revise cycles, lessons needing attention, cost and image reuse, and the evidence-backed proposals. Core's `DATA_UNAVAILABLE` on these two reads is how it says "no runs yet", so it is shown as the empty state with a retry.

**Mentor quality C.24.** The dashboard needs `view_analytics` and no legacy page existed, so it gets its own console section (`mentorQuality`, `/admin/mentor-quality`) in the route table, the staff navigation (after Learning intel) and the Overview's section list. The page's h1 is the navigation label; the dashboard's status panel heading reads "Data status". Flag actions and the weekly sign-off keep their item-level results without re-reading the page (a re-read would drop a resolved flag, and focus with it); Refresh re-reads.

**The lesson-preview bridge.** A reviewer must approve what a child will see, so the preview is the learner's own player, not a console imitation. Until Lane 2 rebuilds the lesson player, that is the Lesson Engine's `LessonPlayer` in preview mode (nothing graded, saved or tracked), loaded lazily only when a reviewer opens it. The rebuilt console never imports it (the `spec:check` boundary holds): `app-routes/staffConsole.tsx` hands a `renderLessonPreview` function to `StaffContent`. When the learner route switches to the rebuilt player, this one function follows it. The preview entry has no player and says "The lesson player is not available here."

**Removed legacy files** (this lane's own route files; nothing else imported them, proved by `git grep` over `frontend/src`, `frontend/scripts`, `agent` and `.github`): `routes/admin/AdminContentPage.tsx`, `AdminGenerationPage.tsx`, `LearningQualityTab.tsx`, `AlertBanner.tsx`, `AnalyticsCharts.tsx`, `CoachTab.tsx`, `LiveStats.tsx`, `PipelineFlow.tsx`, `RunCompare.tsx`, `RunTimeline.tsx`, `SlotDetailModal.tsx`, `generationTypes.ts`, `generationI18n.ts`, and their tests (`AdminContentPage`, `LearningQualityTab`, `LiveStats`, `LiveStats.realtime`, `AdminGenerationPage`, `PipelineFlow`). ## Decisions taken on the SPEC's conservative default (proposals for owner review)

1. **Staff grants on a superadmin.** G.1's constraint that no permission label is displayed unless it restricts something: a superadmin opens every section, so the holder sheet shows "Superadmins open every section." instead of four switches (the legacy dialog showed switches for superadmins too). The grants are still listed in the grant history.
2. **Funnel on Users only with `view_analytics`.** The legacy card requested analytics endpoints with any grant and hid the 403. It is now asked for only with the analytics grant; a `manage_users`-only admin does not see it.
3. **Audit filters.** The inventory's "filter by action, actor, subject and date" is implemented on the server; the action choice lists the actions of the loaded page (plus the applied one), as the legacy dropdown did. A free-text action field would need a list of all actions from Core, which it does not expose.
4. **Sheets for details** (02 §9.8 layer order; 06 §4 "details behind a tap") instead of the legacy centred dialogs; confirmations stay dialogs.
5. **Report queue page size**: 200 (Core's cap) instead of 50, with no paging, because Core's `/admin/reports` returns `total = cases.length`, so a true pager is not possible without a Core change.
6. **Metric tiles** are one column below a 300 px container, two across up to 480 px, then balanced rows (3, 4, 5 or 6 across by count). Three tiles on a phone read 2 + 1: three across does not fit a label's longest word at 375 px.
7. **Mentor quality is its own console section** (W2T.2). C.24 is read behind `view_analytics`, so it cannot live on Content (`manage_content`); Analytics & Health and Learning intel are still legacy bodies. Proposal: keep the section; the alternative is to fold it into Learning intel when that page is rebuilt.
8. **Every course status change is confirmed** (W2T.2). The legacy page published, unpublished and archived on one press. Publishing makes content child-visible and archiving takes it out of the catalog, so both now need a keep-first confirmation (02 §9.8).
9. **The lesson preview uses the learner's current player** (W2T.2), handed in by the route host, until Lane 2's rebuilt player replaces it. A console-only renderer would let a reviewer approve something a child never sees. Question: confirm this bridge, or require the preview to wait for the rebuilt player.
10. **Live activities without a recorded topic type** (sampled before S06.12) say "Not recorded" instead of being shown as everyday topics. Proposal: keep; Core's governance log already classifies every new item.
11. **Naming C.24 owners has no screen yet.** Core's `POST /admin/mentor-quality/owners` (manage_users) exists; the S06.13 dashboard shows which roles have nobody named but offers no form, and no legacy screen had one. Proposal: add the owner form to Roles & Access in a later checkpoint, behind `manage_users`, audited like the other grants.
12. **Generation stays read-only** (OD-23). No console action starts, pauses or re-runs Forge; the high-failure alert says "Consider pausing the run", which is an operator action outside the console, as before.

13. **Insights is a view of Learning intel, not its own menu entry** (W2T.3, G.5). The legacy console folded Insights into Learning intel on purpose (two panels answering one question with different numbers); the rebuilt Learning intel has a view named "Insights", its menu entry reaches it, and `/admin/insights` opens it. Proposal: accept this as G.5's "in the navigation"; the alternative is a separate "Insights" menu entry (a Lane 0 navigation change).
14. **No ranking of learners** (W2T.3, DP-05). The legacy People tab ranked learners by an engagement score; the dark-pattern gate forbids a leaderboard or ranking in rebuilt UI, and the rebuilt People view shows churn risk only (worst first, for triage, no rank, no names). Core's intel file export still carries the engagement sheet it renders. Question: keep it this way, or approve an aggregated engagement distribution (no per-learner order).
15. **Learner names only with manage_users** (W2T.3, G.6). The legacy directory joined learner names from `/admin/users` for anyone who could open it (a view_analytics-only admin got a refused read and "Private learner"). Proposal: keep names behind manage_users; analytics work uses short ids.
16. **One breakdown at a time** (W2T.3). The legacy page fired fourteen Plausible breakdowns and twelve Umami ones on open; the rebuilt views show one chosen breakdown each, with the same dimensions available. Proposal: keep.
17. **Exclusion actions without a confirmation** (W2T.3). Excluding and revoking are audited by Core, reversible, and forward-only; the page says so before any action. Proposal: keep them one press, as the legacy page did.
18. **Trend granularity** (W2T.3): day, week or month. The warehouse also accepts hour; an hourly series over a year is thousands of points the chart would only average. Proposal: keep the three.
