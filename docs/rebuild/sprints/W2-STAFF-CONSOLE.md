## Implementation and rationale

**Where things live.** `frontend/src/rebuild/staff/console/`: `staffConsoleApi.ts` (hand-mirrored wire shapes with arrival shape checks, the `StaffApi` interface, `useStaffRead`, `staffViewer`), `staffConsoleCopy.ts`, `ConsoleParts.tsx` (page frame, metrics, facts, load failure, pager, copy-id, share bars), `DailyChart.tsx`, one file per screen, `staffConsole.css`, and `staffConsoleFixtures.{json,ts}` (the preview and the audit's synthetic Core answer from the same JSON). The rebuilt files import nothing outside `src/rebuild` and `src/i18n` (`spec:check` boundary): the route hosts in `frontend/src/app-routes/staffConsole.tsx` hand them Core (the app's own client, the staff member's session token; a failed fetch while the browser is offline becomes `OFFLINE`) and the grants from the auth context. `app-routes/staff.tsx` lazy-loads the hosts for the six sections; `app-routes/staffGrants.ts` marks them `rebuilt` and exports `isRebuiltStaffPath`.

**Grants.** `staffViewer` reads grants as Core's `requireAdminPermission` does: only an admin's named grants count and a superadmin holds all. The Overview's section list mirrors `STAFF_ROUTE_GRANTS` (pinned by `app-routes/__tests__/staffConsole.test.tsx`). A section the viewer cannot open is neither linked nor requested; a direct link is refused by the unchanged route guard (verified: no console read happens). A read refused by Core with 403 (a grant withdrawn after the page opened) shows "No access to this" with a retry.

**Overview S1.** Legacy: six KPI tiles, a quick-actions grid with one-line descriptions, content status bars, a role distribution, retention buckets and weakest topics, a health strip. Rebuilt: the same content by grant; the metrics say words plus numbers; content status as labelled share bars with the count and share written; the review queue as a notice with a "Review lessons" link; service health says "Every service answers" or how many do not, and each monitor carries a glyph and a word (02 rule 6); "Health monitoring is not set up here" when Core answers `PULSE_UNCONFIGURED`. Section links use the staff navigation's own labels (`rebuild-core.json`), so a page title and its menu entry never differ.

**Users S3 (A.5).** Legacy: KPI tiles, a funnel card, role/locale/age distributions, a recharts signup timeline with range presets and a daily/cumulative switch, search and role chips, a table, a detail dialog with the revoke form. Rebuilt with every capability kept: the funnel card is shown and requested only with `view_analytics` (the legacy card asked for it with any grant and hid a 403); the signup timeline is our own single-series bar chart (one hue, average rule, period and metric as segmented controls, total/average/peak/change written as text, a readout of the hovered or latest day) instead of recharts' gradient area; the table collapses to cards below 840 px; the details sheet puts the person's name, then parent verification (status chip; reason field; revoke behind a keep-first confirmation naming the person), then the read-only facts with "Copy ID".

**Roles & Access S10.** Legacy: KPI tiles, role distribution with last change, a review-due count, a grant form (user id, role dropdown, justification for Tutor), a candidate search dialog, a holders table with inline revoke chips and a manage-access dialog with permission switches and assignment history. Rebuilt: the G.4 card now lists each due grant (person, role, grant date) with a "Manage" button instead of a bare count; the grant form checks the id shape before calling Core and names the database's refusal (`ROLE_REJECTED`); the holder sheet holds roles (each removal confirmed), staff-grant switches (the design system's `Switch`, state in words) and the grant history (roles and staff grants, who granted, when).

**Audit log S9.** Legacy filtered by action only (from the loaded page) plus a client search. Rebuilt: action, actor id (checked as a full UUID), subject and a date range go to Core's `AuditQuerySchema` (exact matches, inclusive days) from a filters sheet; an active-filter notice shows how many are on with "Clear filters"; the page search still narrows only the loaded page; server paging with the range in words; the detail sheet says the record cannot be changed and shows the JSON detail wrapped, never scrolled sideways.

**Reports (E.3).** Legacy: a table and a detail dialog with Resolve. Rebuilt: open/pattern/open-report counts, a status filter, origin and status as glyph-plus-word chips, the case sheet with each report's category, date, short reporter id and capped note, a note for automatic pattern cases, and Resolve behind a confirmation that says the decision goes to the audit log. The queue now asks Core for its full page (limit 200; the legacy page used the default 50).

**Emails S4.** Legacy: six KPI tiles, a recharts trend, status/template/locale breakdowns, search and dropdown filters on the server, a table with a separate phone card list, a detail dialog, a refresh action, a partial-failure card. Rebuilt with the same capabilities: the history is one `DataTable` (cards below 840 px), the search is debounced (300 ms) before it reaches Core, the totals and the history fail and retry separately.

**Shared decisions.** Every string is in `rebuild-staff.json` → `staffConsole`, keyed `<screen>.<role>.<key>`, so the copy-budget test reads each string's role from its path and fills placeholders with the longest real value. Role names: Superadmin, Admin, Bigfounder, Tutor (the `parent` role, OD-6), Child, Universal. No character, no celebration, no motion of our own; system glyphs only (check, cross, info, warning, chevron, close); tokens only, light and dark; 48 px targets; layout by container width (metrics balance their rows by their own container: no orphan tile).

**Defect found on the real route and fixed in the design system (Lane 0 file, minimal).** On `/admin/reports` a real press on "Open" opened the case sheet but focus fell to `<body>` while the page behind was already inert: under React's development double effects, `useLayerHost` appended a host, removed it and appended a second one, and a render still holding the first (removed) host ran the focus trap there. `rebuild/design/overlays.tsx` `useModal` now treats a disconnected host as not ready (one line). Pinned by a StrictMode test in `StaffConsole.test.tsx` that fails without the fix and passes with it; the users, audit and email sheets had passed by timing only.

**Removed legacy files** (this lane's own route files; nothing else imported them, proved by `git grep`): `routes/admin/AdminOverviewPage.tsx`, `AdminUsersPage.tsx`, `AdminRolesPage.tsx`, `AdminAuditPage.tsx`, `AdminReportsPage.tsx`, `AdminEmailDashboard.tsx`, `UsersFunnelCard.tsx`, `SignupTimeline.tsx`, `adminNav.ts`, and their tests (`AdminOverviewPermissions`, `AdminUsersPage`, `AdminGovernancePages`, `AdminEmailDashboard`, `SignupTimeline`), whose assertions are carried by the new tests. `adminPermissions.test.tsx` now derives the visible sections from the staff shell's navigation instead of `adminNav.ts`; its guard assertions are unchanged. `adminShared.tsx` stays (the legacy Content, Generation, Intel and Analytics pages still use it).

**Changes outside the lane's files (Lane 0 or shared), each minimal:**

1. `app-shell/AppLayouts.tsx` `StaffShellLayout`: a rebuilt console path renders its screen directly in the shell's content area; every other path keeps `LegacyBody` (one conditional, reading `isRebuiltStaffPath` from this lane's `staffGrants.ts`).
2. `rebuild/design/overlays.tsx` `useModal`: the host race fix above.
3. `frontend/package.json`: the `verify:staff-console` script.
4. `frontend/scripts/audit-rebuild.mjs`: an optional `AUDIT_READY_MS` (default 15000, unchanged behaviour) for how long a state may take to become ready; needed because the shared machine was saturated (see the log).

## Decisions taken on the SPEC's conservative default (proposals for owner review)

1. **Staff grants on a superadmin.** G.1's constraint that no permission label is displayed unless it restricts something: a superadmin opens every section, so the holder sheet shows "Superadmins open every section." instead of four switches (the legacy dialog showed switches for superadmins too). The grants are still listed in the grant history.
2. **Funnel on Users only with `view_analytics`.** The legacy card requested analytics endpoints with any grant and hid the 403. It is now asked for only with the analytics grant; a `manage_users`-only admin does not see it.
3. **Audit filters.** The inventory's "filter by action, actor, subject and date" is implemented on the server; the action choice lists the actions of the loaded page (plus the applied one), as the legacy dropdown did. A free-text action field would need a list of all actions from Core, which it does not expose.
4. **Sheets for details** (02 §9.8 layer order; 06 §4 "details behind a tap") instead of the legacy centred dialogs; confirmations stay dialogs.
5. **Report queue page size**: 200 (Core's cap) instead of 50, with no paging, because Core's `/admin/reports` returns `total = cases.length`, so a true pager is not possible without a Core change.
6. **Metric tiles** are one column below a 300 px container, two across up to 480 px, then balanced rows (3, 4, 5 or 6 across by count). Three tiles on a phone read 2 + 1: three across does not fit a label's longest word at 375 px.
