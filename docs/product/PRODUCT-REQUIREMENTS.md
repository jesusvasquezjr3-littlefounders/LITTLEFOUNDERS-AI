# Product requirements

> What LittleFounders is, for whom, and why. The source of truth for scope.

> **Status: scaffold.** The structure is set; nothing below that is not marked as current state has been decided. Fill it in with the owner, then change the status to `draft` and, once approved, `accepted`.

## Role

Agents and humans read this to know what to build and, just as important, what not to. An agent must never invent a feature, a persona or a priority that is not written here. It contains outcomes and acceptance criteria, never implementation.

## Read this when

- Starting any feature, to confirm it is in scope.
- Writing or reviewing a technical requirements document.
- Deciding priority or cutting scope.

## To define

- [ ] Vision and the problem being solved.
- [ ] Personas: who uses the product, their ages, and who gives consent for a minor.
- [ ] Goals, non-goals and explicit out-of-scope items.
- [ ] Feature catalog: one ID per feature (F-001, F-002, ...), priority, and acceptance criteria.
- [ ] Success metrics and how each is measured.
- [ ] Legal, age and safety constraints that bound the product (no real money is ever represented).
- [ ] Open questions for the owner.

## Current state

- The product was restarted from zero on 2026-10-09. Only the landing page (hero and problem sections) exists; its calls to action do nothing yet.
- The owner set the first product principles on 2026-10-10 after the reference mapping was read: mistakes are never punished, one primary button per screen, value before data, rewards one idea per screen, no commercial pressure and a free layer for everything, Seeds as the currency, self-declared permission at sign-up, and finance content later. They are recorded one by one in [[DECISIONS]] (D-018 to D-026). No feature is defined yet.
