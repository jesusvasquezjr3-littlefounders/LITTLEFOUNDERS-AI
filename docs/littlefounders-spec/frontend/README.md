# LittleFounders — Frontend (Bible v3, mockup v2.1)

This package is the frontend design system: the **Frontend Bible** (the evidence-graded
rule set an AI agent or a human designer follows to build any screen) and the **mockup**
that was built and verified against it.

## What changed in v3 (2026-09-21)

The owner reviewed the v2.1 screenshots and added three binding decisions (in
`13-OWNER-DECISION-LOG.md`, Product package):

- **OD-13, Copy budget:** too much text. New chapter `frontend-bible/06-COPY-BUDGET.md`
  sets numeric limits per text role, a first-view limit and layering for detail. A new
  tool, `verification-tools/copy-budget-audit.reference.mjs`, checks it. The mockup is
  over budget (142 findings, deviation K40, full list in `mockup/COPY-BUDGET-FINDINGS.md`).
- **OD-14, Our own iconography and visual assets:** non-negotiable, like shapes and colours.
  New chapter `frontend-bible/07-ICONOGRAPHY-AND-VISUAL-ASSETS.md`: at most 24 generic
  system glyphs; everything meaningful is our own SVG, WebP or Lottie, generated by the
  frontend agent in the house style. The Mentor characters are always rendered from the
  real 3D models and the pose catalogue in the project folder. The mockup's icons and art
  are placeholders (K41).
- **OD-15, The Mentor is a 3D character on its Diorama:** new chapter
  `frontend-bible/08-MENTOR-STAGE.md`. The legacy Mentor chat UI and the legacy buttons of
  the current application are deleted and rebuilt, never restyled. The mockup's
  chat-style Mentor screen is not the design (K42).
- `02-FOUNDATIONS.md` is now v3: new decisions D11–D13 and mechanical rules 19–23.

## How to read this, in order

1. **`frontend-bible/01-RESEARCH-FOUNDATION.md`** — the evidence base behind the rules:
   colour, shape, gamification and accessibility for this audience, each claim graded A–D.
2. **`frontend-bible/02-FOUNDATIONS.md`** — the core rule set and the file to hand an AI
   agent: decision log (D1–D13), scope/access/naming and language/platform constraints
   (§1.1–1.2), mechanically checkable rules, `DESIGN.md` YAML tokens, colour, dual mode,
   typography, the Text Fit Contract, touch targets, gamification and motion summary.
3. **`frontend-bible/03-PROPORTIONS-AND-COMPOSITION.md`** — why a layout reads as
   machine-made or human-made, and the composition rules that follow.
4. **`frontend-bible/04-MOTION.md`** — the evidence on animation "juice", the duration and
   easing tokens (five tokens in three categories), reduced motion, and the orchestrated
   patterns.
5. **`frontend-bible/05-TEACHING-VISUALS.md`** — the board, `viz` tokens and the
   interaction/accessibility contract for every chart, mathematical, logic and money visual.
6. **`frontend-bible/06-COPY-BUDGET.md`** — how much text each element may carry, and
   where the rest goes.
7. **`frontend-bible/07-ICONOGRAPHY-AND-VISUAL-ASSETS.md`** — system glyphs vs our own
   assets, the house style, the real 3D characters, the asset manifest and the review gate.
8. **`frontend-bible/08-MENTOR-STAGE.md`** — the Mentor screen: the character on the
   Diorama, the speech plate, the board, reply chips, states, layout, fallbacks and the
   acceptance checklist that retires the legacy UI.
9. **`mockup/littlefounders-mockup.html`** + **`mockup/KNOWN-DEVIATIONS.md`** — the visual
   reference (one self-contained file, 17 routes, EN/ES/PT, light/dark; a control bar
   switches route, language, theme, width and text stress) and the list of what not to copy.
   Scope comes from the product's screen inventory and requirements, not from the mockup.
   K40–K42 are open on purpose: the mockup's copy, icons/art and Mentor screen are not the
   design.
10. **`verification-tools/`** — the three audit scripts.

## Verification tools

| File | What it checks |
|---|---|
| `text-fit-audit.reference.mjs` | The Text Fit Contract (`02` §7): ellipsis, line-clamp, clipping, text outside the frame, words wider than their box, tap targets under 48 px, horizontal scroll. 41 states (17 routes and their state variants) × EN/ES/PT × light/dark × 320/375/768/1280 px × normal/+40% text = 1,968 configurations, run with normal text and again with WCAG 1.4.12 text spacing. Skips visually-hidden (`.sr-only`-style) elements. |
| `copy-budget-audit.reference.mjs` | The Copy Budget (`06` §3): words per action, heading, body, prompt, option, Mentor turn and narrative, sentences per body text, and the words in the first view of app screens, per state × EN/ES/PT (ES/PT ×1.25). Uses `data-copy-role` when components declare it, heuristics otherwise. |
| `proportion-audit.reference.mjs` | Composition rules (`03` §5) on the rendered page: off-grid spacing, off-scale type, measure, uniform card rows, heading:body ratio, hero split, competing accent buttons, section rhythm, tap-target gaps. 41 states × 4 widths × 3 languages = 492 page states. |

v2 changes: the text-fit tool now drives the mockup correctly (`#route=` and `S.route`;
v1 used `#screen=` / `S.screen`, audited only the landing page and passed vacuously),
covers all 17 routes and their state variants, refuses to run if the routes do not
render differently, and no longer reports the visually-hidden staff-table header as
clipped. Both tools now use plain `puppeteer-core` with a local Chrome/Chromium instead
of `@sparticuz/chromium`, and exit non-zero on findings (usable in CI).

**Run** (Node 18+):

```sh
npm install puppeteer-core
export CHROME_PATH=/path/to/chrome-or-chromium      # required; the scripts stop with a message if unset
node verification-tools/proportion-audit.reference.mjs mockup/littlefounders-mockup.html proportion-report.json
node verification-tools/text-fit-audit.reference.mjs mockup/littlefounders-mockup.html both   # or: audit | spacing
node verification-tools/copy-budget-audit.reference.mjs mockup/littlefounders-mockup.html     # JSON=out.json for the full list
```

Optional environment variables are listed at the top of each script (`ROUTES`, `WIDTHS`,
`LANGS`, `THEMES`, `VERBOSE`, `MOTION`; the copy-budget audit also takes `FOLD` and `JSON`). All three scripts are still coupled to the mockup's
state hooks (`S`, `render()`); auditing the real application needs a new driver with the
same checks.

**Results on the v2.1 mockup** (independently re-run): proportion audit, 492 page states, **0 findings**. Text fit, 1,968 configurations with normal text and 1,968 with WCAG 1.4.12 text spacing, **0 issues** in either. 0 JavaScript errors. Copy budget (added in v3): **142 distinct findings** (59 in English). This is the baseline recorded as K40, not a regression.

## What's deliberately not in this package

- **Copy and translation quality.** Mockup strings are placeholder translations for
  layout testing. Production copy is AI-translated from the controlled glossary (`02` §1.2);
  native review of registration, consent and money screens is recommended, not yet confirmed.
- **Final art and 3D.** The four Mentor characters, the Diorama and the pose catalogue live
  in the main project folder, not in this package. Our own icons, illustrations and motion
  are generated by the frontend agent under `07`; nothing in the mockup is final art.
- **Screens the mockup does not cover** (settings, badge sharing, full profile/social, the
  admin console beyond content review, and the rest of the teaching-visual catalogue in
  Appendix P). They are designed from the product requirements in this visual language.
