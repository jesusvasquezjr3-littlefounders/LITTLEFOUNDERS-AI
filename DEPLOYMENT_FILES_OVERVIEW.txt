╔══════════════════════════════════════════════════════════════════════════════╗
║ OPCIÓN 1: ELASTIC BEANSTALK (Más Fácil) ⭐ RECOMENDADO PARA EMPEZAR         ║
╚══════════════════════════════════════════════════════════════════════════════╝

  $ pip install awsebcli
  $ eb init -p docker littlefounders --region us-east-1
  $ eb create littlefounders-prod
  $ eb setenv DATABASE_URL="..." SECRET_KEY="..."
  $ npm run build
  $ eb deploy

  ⏱️  Tiempo total: ~20 minutos
  💰 Costo estimado: ~$50/mes

╔══════════════════════════════════════════════════════════════════════════════╗
║ OPCIÓN 2: SCRIPT AUTOMATIZADO (deploy.sh) ⭐ MÁS RÁPIDO                     ║
╚══════════════════════════════════════════════════════════════════════════════╝

  $ chmod +x deploy.sh
  $ ./deploy.sh production eb     # Para Elastic Beanstalk
  $ ./deploy.sh production ecs    # Para ECS
  $ ./deploy.sh production ec2    # Para EC2

  ⏱️  Tiempo total: ~15-40 minutos (según método)

╔══════════════════════════════════════════════════════════════════════════════╗
║ OPCIÓN 3: GITHUB ACTIONS (CI/CD Automático) ⭐ MEJOR PARA PRODUCCIÓN        ║
╚══════════════════════════════════════════════════════════════════════════════╝

  1. Agregar secrets a GitHub:
     - AWS_ACCESS_KEY_ID
     - AWS_SECRET_ACCESS_KEY

  2. Push a main:
     $ git add .
     $ git commit -m "Deploy to AWS"
     $ git push origin main

  3. GitHub Actions se ejecuta automáticamente

  ⏱️  Tiempo total: ~10 minutos setup + deployment automático

✅ Variables de Entorno:

Elastic Beanstalk:
  eb deploy ........................ Desplegar aplicación
  eb logs .......................... Ver logs
  eb status ........................ Ver estado
  eb health ........................ Ver salud de la aplicación
  eb open .......................... Abrir en navegador

ECS:
  aws ecs update-service ........... Actualizar servicio
  aws ecs describe-services ........ Ver estado de servicios
  aws logs tail /ecs/littlefounders  Ver logs

EC2:
  ssh -i key.pem ubuntu@instance ... Conectar al servidor
  sudo systemctl status backend .... Estado del backend
  sudo systemctl restart nginx ..... Reiniciar Nginx
  sudo journalctl -u backend -f .... Ver logs en tiempo real

Docker:
  docker-compose up -d ............. Iniciar contenedores
  docker-compose logs -f ........... Ver logs
  docker-compose down .............. Detener contenedores
  docker ps ........................ Ver contenedores activos

│                            🆘 TROUBLESHOOTING                                │
└──────────────────────────────────────────────────────────────────────────────┘

❌ Error: Cannot connect to database
   → Verificar Security Group del RDS
   → Verificar DATABASE_URL en variables de entorno
   → Probar conexión con psql

❌ Error: 502 Bad Gateway
   → Ver logs del backend (eb logs o CloudWatch)
   → Verificar que el backend está corriendo
   → Verificar configuración de Nginx

❌ Error: Build failed
   → Revisar buildspec.yml
   → Verificar permisos IAM
   → Ver logs de CodeBuild

❌ Error: Port already in use
   → Cambiar puerto en docker-compose.yml
   → Detener otros servicios en el puerto
   → Usar: sudo lsof -i :PORT
